# Cashflow Operation Sheets

## Цель
Разделить создание операций по типам (`доход`, `расход`, `перевод`) на отдельные `bottom sheet`, чтобы у каждого сценария был независимый UX и эволюция без усложнения общего редактора.

## Текущая реализация
- `CashflowIncomeTransactionSheet`: двухшаговый поток.
  - Стартовый системный набор доходов: 8 категорий (`Зарплата`, `Фриланс`, `Бизнес`, `Инвестиции`, `Аренда`, `Подарок`, `Премия`, `Другое`) с emoji-иконками и RU/EN-локализацией.
  - Порядок базовых доходов оптимизирован под частые сценарии ввода: `Зарплата`, `Фриланс`, `Бизнес`, `Премия`, `Инвестиции`, `Аренда`, `Подарок`, `Другое`.
  - Emoji сделаны семантически ближе к источнику поступления: `💳`, `🛠️`, `🏢`, `🏅`, `📈`, `🏘️`, `🎁`, `📦`.
  - Шаг 1: экран в стиле `cashflow` (черный фон, неоновые границы, крупный заголовок, pill-кнопка `Закрыть`), выбор месяца, блок итога дохода за месяц, поиск категорий, плитки категорий, FAB добавления категории внизу справа.
  - Шаг 1.4: в шапке справа есть кнопка `?` с краткой справкой по сценарию: как выбрать категорию, как добавить категорию через `+`, как открыть редактирование/удаление через удержание (long press) и что при удалении операции переносятся в безопасную системную категорию.
  - Шаг 1.0: месячный блок показывает диапазон дат выбранного месяца (`dd.MM.yyyy — dd.MM.yyyy`) под заголовком месяца.
  - Шаг 1.3: в карточке категории под названием отображается сумма дохода этой категории за выбранный месяц.
  - Шаг 1.2: блок "Управление операциями" с переходами на `Регулярные` и `Запланированные` (без подзаголовков).
  - Шаг 1.1: у всех видимых категорий доступно контекстное меню по long press на плитке (редактирование + удаление, кроме fallback-категории `Другое`).
  - Шаг 2: ввод данных через `CashflowTransactionEditorView` в embedded-режиме (без выбора типа/категории), с отображением выбранной категории над блоком "Основная информация".
- `CashflowExpenseTransactionSheet`: двухшаговый поток с тем же UX, но для расхода.
  - Шаг 1: экран в стиле `cashflow` (единая визуальная система с основным экраном кэшфлоу), выбор месяца, блок итога расхода за месяц, поиск категорий, плитки категорий, FAB добавления категории внизу справа.
  - Шаг 1.5: сверху под итогом месяца есть отдельный entry-point `Mass import` для пакетного внесения расходов за выбранный месяц.
    - поддерживает два режима: ручной ввод строк и OCR по банковским скринам,
    - использует компактный ряд `Валюта` + `Карта`, где выбор карты фильтруется по выбранной валюте (как в обычном экране расхода),
    - перед сохранением показывает общий итог, необязательный `statement total`, остаток до суммы выписки и кнопку `Send remainder to Other`,
    - имеет toggle `Update card balance`, чтобы можно было занести историю без изменения текущего остатка карты.
  - Шаг 1.4: в шапке справа есть кнопка `?` с краткой справкой по сценарию: как выбрать категорию, как добавить категорию через `+`, как открыть редактирование/удаление через удержание (long press) и что при удалении операции переносятся в безопасную системную категорию.
  - Шаг 1.0: месячный блок показывает диапазон дат выбранного месяца (`dd.MM.yyyy — dd.MM.yyyy`) под заголовком месяца.
  - Шаг 1.3: в карточке категории под названием отображается сумма расхода этой категории за выбранный месяц.
  - Шаг 1.2: блок "Управление операциями" с переходами на `Регулярные` и `Запланированные` (без подзаголовков).
  - Шаг 1.1: у всех видимых категорий доступно контекстное меню по long press на плитке (редактирование + удаление, кроме fallback-категории `Другое`).
  - Шаг 2: ввод данных через `CashflowTransactionEditorView` в embedded-режиме (без выбора типа/категории), с отображением выбранной категории над блоком "Основная информация".
- `CashflowTransferTransactionSheet`: отдельный sheet-обертка с фиксированным типом `transfer`.
- В `CashflowTransactionEditorView` блок выбора карты встроен в секцию `Основная информация`:
  - `Доход` и `Расход`: `Валюта` и `Карта/Счет` собраны в один компактный ряд, при этом валюта остается первым выбором.
  - `Доход` и `Расход`: список берет только продукты, реально добавленные в `Финансы`, и фильтруется по выбранной валюте операции.
  - `Доход`: помимо карт в списке доступны и денежные счета из `Финансов` (cash-accounts на базе инвестиций категории `other`).
  - `Доход` и `Расход`: текст блока упрощен; toggle `Update card balance` теперь явно объясняет сценарий восстановления истории без изменения текущего остатка.
  - Поле `Сумма` поддерживает копейки (до 2 знаков после разделителя) и принимает `,` и `.` в качестве десятичного разделителя.
  - Селектор `Валюта операции` закрепляет `primary currency` из Профиля только как справочный pin; выбор валюты операции не меняет глобальную `primaryCurrencyCode`.
  - `Перевод`: строка `Валюта` идет сразу после `Суммы`, затем `С карты`/`На карту`.
- Help по `?` на экранах доходов/расходов:
  - больше не перечисляет общие очевидные действия;
  - вместо этого объясняет практический кейс восстановления месяца, когда пользователь обновлял остатки карты, но не заносил сами траты/доходы в историю;
  - подчеркивает правило: сначала валюта, потом карта/счет в этой же валюте, а при уже корректном текущем остатке можно выключить обновление баланса и восстановить только историю.
- `CashflowScheduledTransactionsView`: отдельный экран управления будущими денежными событиями.
  - Режим `recurring`: показывает только шаблоны с `recurrenceRule = monthly`, дает создавать/редактировать/удалять регулярные операции.
  - Режим `planner`: объединяет в одном UX ежемесячные шаблоны и разовые будущие операции.
  - В `planner` сверху есть summary-card с ближайшим событием и счетчиками `Ежемесячно` / `Разово`, ниже переключатель `Календарь / Список`.
  - В `planner` календарь проецирует ежемесячные шаблоны на выбранный месяц, а для выбранного дня показывает agenda конкретных списаний/поступлений.
  - День в календарной ячейке центрируется по обеим осям и использует `monospacedDigit()`, чтобы сетка не "плыла" при смене дат.
  - В `planner` list-mode разделяет элементы на две секции: повторяющиеся каждый месяц и разово запланированные.
  - Создание из `planner` идет через picker: `Ежемесячно` или `Разово`.
  - В `CashflowTransactionEditorView` настройка `Повтор` переведена в Apple-like flow: отдельный экран выбора частоты с явной галочкой текущего режима.
  - В `Повтор` доступны только `Не повторять`, `Раз в неделю` (с мультивыбором дней недели) и `Раз в месяц`; интервалы длиннее месяца скрыты из UI.
  - Удаление доступно через swipe влево по карточке (`swipeActions`, поддерживается full swipe) и через контекстное меню; перед удалением всегда показывается confirm alert.
- `CashflowTransactionsHistoryView`: tap по операции открывает экран деталей операции.
  - На экране деталей доступны `Edit transaction` и `Delete transaction` в modern iOS glass-стиле.
  - Для удаления есть выбор с явной формулировкой:
    `Удалить + обновить остатки` (обновляются остатки затронутых счетов/карт) или
    `Удалить только из истории` (удаляется запись без немедленного пересчета остатков).

## Точки входа
- `CashflowView`: при `creatingTransactionType` теперь выбирает отдельный sheet по типу операции.
- `MainAppView`: кнопки `Доход` и `Расход` открывают новые отдельные sheet.

## Расширяемость
- Для следующего шага можно внедрять отдельный UX перевода, не затрагивая flow дохода/расхода.
- Общая логика сохранения и валидации остается в `CashflowTransactionEditorView` и `CashflowViewModel`, чтобы избежать дублирования бизнес-правил.
- Пакетный импорт расходов тоже сохраняется через `CashflowViewModel`, одним `save`, с общей проверкой остатка по карте и единым обновлением баланса.
- Отбор регулярных и запланированных операций инкапсулирован в `CashflowViewModel` (`recurringTemplates`, `plannedOneTimeTransactions`, `scheduledPlannerEntries`, `scheduledCalendarEntries`, `nextOccurrenceDate`) и покрыт unit-тестами.

## EN Terminology Contract
- Базовый термин для записи в истории: `transaction` (не `operation`).
- Для фильтров и карточек использовать `Income` / `Expenses`; не использовать `Top-ups`.
- Для RU-локали использовать `Доход` / `Доходы` в зависимости от контекста; не использовать `Пополнения` для cashflow-доходов.
- Для секции редактирования использовать `Details` вместо `Main info`.
- Для метрики изменения стоимости активов использовать `Asset revaluation`.

## Visual Contract (Cashflow main screen)
- Неон остается акцентом, но используется дозированно:
  - неоновая обводка только для внешних карточек периода/сводки и primary CTA,
  - внутренние строки сводки без отдельных рамок, только тонкие separators.
- Иерархия типографики:
  - вторичный текст: `15 semibold/medium` с повышенным контрастом,
  - ключевые суммы строк: `21 semibold`,
  - `Итого`: `30 bold` с `numericText` переходом.
- Единая семантика цвета суммы:
  - `positive` -> единый неон-зеленый,
  - `negative` -> единый неон-красный,
  - `neutral` -> secondary text.
- Верхняя панель упрощена:
  - слева `Back`,
  - справа один сегмент-контрол (`Валюта` / `История`) вместо двух независимых капсул.
- Переключатель периода перенесен внутрь блока графика и находится в его верхней части.
- Карточки `Расход` и `Доход` в full screen-графике ведут в историю с фильтром по выбранному периоду.
- В full screen-графике убрана шапка со стрелками; окно периода выравнивается по текущему периоду справа, недостающие периоды слева заполняются плейсхолдерами.
- В full screen-графике `Result` в верхней части теперь приоритетный акцент:
  - увеличенный размер суммы,
  - capsule-highlight по тону значения (green/red/neutral), чтобы итог считывался первым.
- Карточки `Расход` и `Доход` в full screen-графике визуально облегчены (уменьшена типографика и высота), чтобы не спорить с главным итогом.
- Внизу full screen-графика добавлен скрываемый hint:
  - объясняет выбор окна `Visible range`,
  - скрытие сохраняется через `HintsVisibilityPrefs` (`cashflow.expanded_chart.bottom_hint`).
- Bottom action buttons:
  - `Доход` primary (filled neon-glass),
  - `Расход` и `Перевод` secondary (тонкая обводка),
  - при узкой ширине экрана автоматически включается compact-метрика кнопок
    (меньше иконка/отступы/шрифт), чтобы `Перевод` не обрезался.
- Добавлены micro-interactions:
  - мягкая анимация переключения периода (`easeInOut ~0.2s`),
  - spring-анимация обновления итоговой суммы,
  - light haptic на периодных и action-кнопках.

## Visual Contract (Income / Expense sheets)
- Единый современный стиль с `Cashflow`:
  - glass-подложки и мягкие обводки вместо тяжелых рамок,
  - неон сохранен как акцент, а не как базовый контур каждого элемента.
- В шапке листа добавлен явный контекст экрана:
  - `Доходы` / `Затраты` + компактная кнопка закрытия.
- Текущая итерация (compact mode):
  - текстовый заголовок в шапке скрыт, оставлена только компактная кнопка закрытия,
  - блок периода сделан ниже по высоте, период показывается сразу под месяцем.
- Блок месяца:
  - контролы назад/вперед в compact rounded стиле,
  - плавная анимация смены месяца + light haptic.
- Блок итога месяца:
  - оставлена только крупная сумма (без строк `Итого ...`),
  - `numericText`-анимация на обновлении суммы.
- Карточки категорий и управления:
  - упрощены контуры, снижена визуальная шумность,
  - акцентные градиенты оставлены с меньшей интенсивностью,
  - в управлении оставлены только заголовки `Регулярные` и `Запланированные` без подзаголовков.
