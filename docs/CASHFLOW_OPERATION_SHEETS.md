# Cashflow Operation Sheets

## Цель
Разделить создание операций по типам (`доход`, `расход`, `перевод`) на отдельные `bottom sheet`, чтобы у каждого сценария был независимый UX и эволюция без усложнения общего редактора.

## Текущая реализация
- `CashflowIncomeTransactionSheet`: двухшаговый поток.
  - Шаг 1: выбор месяца, блок итога дохода за месяц, поиск категорий, плитки категорий, плитка добавления категории.
  - Шаг 1.2: блок "Управление операциями" с переходами на:
    - `Регулярные доходы` (ежемесячные шаблоны доходов),
    - `Запланированные доходы` (разовые будущие операции доходов).
  - Шаг 1.1: у пользовательских (custom) категорий доступно контекстное меню с редактированием и удалением.
  - Шаг 2: ввод данных через `CashflowTransactionEditorView` в embedded-режиме (без выбора типа/категории), с отображением выбранной категории над блоком "Основная информация".
- `CashflowExpenseTransactionSheet`: двухшаговый поток с тем же UX, но для расхода.
  - Шаг 1: выбор месяца, блок итога расхода за месяц, поиск категорий, плитки категорий, плитка добавления категории.
  - Шаг 1.2: блок "Управление операциями" с переходами на:
    - `Регулярные расходы` (ежемесячные шаблоны расходов),
    - `Запланированные расходы` (разовые будущие операции расходов).
  - Шаг 1.1: у пользовательских (custom) категорий доступно контекстное меню с редактированием и удалением.
  - Шаг 2: ввод данных через `CashflowTransactionEditorView` в embedded-режиме (без выбора типа/категории), с отображением выбранной категории над блоком "Основная информация".
- `CashflowTransferTransactionSheet`: отдельный sheet-обертка с фиксированным типом `transfer`.
- `CashflowScheduledTransactionsView`: отдельный экран управления регулярными и запланированными операциями.
  - Режим `recurring`: показывает только шаблоны с `recurrenceRule = monthly`, дает создавать/редактировать/удалять регулярные операции.
  - Режим `plannedOneTime`: показывает только будущие операции без автоповтора, дает создавать/редактировать/удалять разовые запланированные операции.

## Точки входа
- `CashflowView`: при `creatingTransactionType` теперь выбирает отдельный sheet по типу операции.
- `MainAppView`: кнопки `Доход` и `Расход` открывают новые отдельные sheet.

## Расширяемость
- Для следующего шага можно внедрять отдельный UX перевода, не затрагивая flow дохода/расхода.
- Общая логика сохранения и валидации остается в `CashflowTransactionEditorView` и `CashflowViewModel`, чтобы избежать дублирования бизнес-правил.
- Отбор регулярных и запланированных операций инкапсулирован в `CashflowViewModel` (`recurringTemplates`, `plannedOneTimeTransactions`, `nextOccurrenceDate`) и покрыт unit-тестами.
