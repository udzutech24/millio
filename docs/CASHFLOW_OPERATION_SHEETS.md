# Cashflow Operation Sheets

## Цель
Разделить создание операций по типам (`доход`, `расход`, `перевод`) на отдельные `bottom sheet`, чтобы у каждого сценария был независимый UX и эволюция без усложнения общего редактора.

## Текущая реализация
- `CashflowIncomeTransactionSheet`: двухшаговый поток.
  - Шаг 1: экран в стиле `cashflow` (черный фон, неоновые границы, крупный заголовок, pill-кнопка `Закрыть`), выбор месяца, блок итога дохода за месяц, поиск категорий, плитки категорий, FAB добавления категории внизу справа.
  - Шаг 1.0: месячный блок показывает диапазон дат выбранного месяца (`dd.MM.yyyy — dd.MM.yyyy`) под заголовком месяца.
  - Шаг 1.3: в карточке категории под названием отображается сумма дохода этой категории за выбранный месяц.
  - Шаг 1.2: блок "Управление операциями" с переходами на:
    - `Регулярные` с подзаголовком `Ежемесячные доходы` (ежемесячные шаблоны доходов),
    - `Запланированные` с подзаголовком `Будущие поступления` (разовые будущие операции доходов).
  - Шаг 1.1: у всех видимых категорий доступно контекстное меню по long press на плитке (редактирование + удаление, кроме fallback-категории `Другое`).
  - Шаг 2: ввод данных через `CashflowTransactionEditorView` в embedded-режиме (без выбора типа/категории), с отображением выбранной категории над блоком "Основная информация".
- `CashflowExpenseTransactionSheet`: двухшаговый поток с тем же UX, но для расхода.
  - Шаг 1: экран в стиле `cashflow` (единая визуальная система с основным экраном кэшфлоу), выбор месяца, блок итога расхода за месяц, поиск категорий, плитки категорий, FAB добавления категории внизу справа.
  - Шаг 1.0: месячный блок показывает диапазон дат выбранного месяца (`dd.MM.yyyy — dd.MM.yyyy`) под заголовком месяца.
  - Шаг 1.3: в карточке категории под названием отображается сумма расхода этой категории за выбранный месяц.
  - Шаг 1.2: блок "Управление операциями" с переходами на:
    - `Регулярные` с подзаголовком `Ежемесячные расходы` (ежемесячные шаблоны расходов),
    - `Запланированные` с подзаголовком `Будущие списания` (разовые будущие операции расходов).
  - Шаг 1.1: у всех видимых категорий доступно контекстное меню по long press на плитке (редактирование + удаление, кроме fallback-категории `Другое`).
  - Шаг 2: ввод данных через `CashflowTransactionEditorView` в embedded-режиме (без выбора типа/категории), с отображением выбранной категории над блоком "Основная информация".
- `CashflowTransferTransactionSheet`: отдельный sheet-обертка с фиксированным типом `transfer`.
- В `CashflowTransactionEditorView` блок выбора карты встроен в секцию `Основная информация`:
  - `Доход` и `Расход`: строка `Карта` находится между `Сумма` и `Валюта`.
  - `Перевод`: строки `С карты`/`На карту` находятся между `Сумма` и `Валюта`.
- `CashflowScheduledTransactionsView`: отдельный экран управления регулярными и запланированными операциями.
  - Режим `recurring`: показывает только шаблоны с `recurrenceRule = monthly`, дает создавать/редактировать/удалять регулярные операции.
  - Режим `plannedOneTime`: показывает только будущие операции без автоповтора, дает создавать/редактировать/удалять разовые запланированные операции.
  - Удаление доступно через swipe влево по карточке (`swipeActions`, поддерживается full swipe) и через контекстное меню; перед удалением всегда показывается confirm alert.

## Точки входа
- `CashflowView`: при `creatingTransactionType` теперь выбирает отдельный sheet по типу операции.
- `MainAppView`: кнопки `Доход` и `Расход` открывают новые отдельные sheet.

## Расширяемость
- Для следующего шага можно внедрять отдельный UX перевода, не затрагивая flow дохода/расхода.
- Общая логика сохранения и валидации остается в `CashflowTransactionEditorView` и `CashflowViewModel`, чтобы избежать дублирования бизнес-правил.
- Отбор регулярных и запланированных операций инкапсулирован в `CashflowViewModel` (`recurringTemplates`, `plannedOneTimeTransactions`, `nextOccurrenceDate`) и покрыт unit-тестами.

## Visual Contract (Cashflow main screen)
- Неон остается акцентом, но используется дозированно:
  - неоновая обводка только для внешних карточек периода/сводки и primary CTA,
  - внутренние строки сводки без отдельных рамок, только тонкие separators.
- Иерархия типографики:
  - вторичный текст: `15 semibold/medium` с повышенным контрастом,
  - ключевые суммы строк: `21 semibold`,
  - `Итого`: `30 bold` с `numericText` переходом.
- Единая семантика цвета суммы:
  - `positive` -> единый неон-зеленый,
  - `negative` -> единый неон-красный,
  - `neutral` -> secondary text.
- Верхняя панель упрощена:
  - слева `Back`,
  - справа один сегмент-контрол (`Валюта` / `История`) вместо двух независимых капсул.
- Bottom action buttons:
  - `Доход` primary (filled neon-glass),
  - `Расход` и `Перевод` secondary (тонкая обводка).
- Добавлены micro-interactions:
  - мягкая анимация переключения периода (`easeInOut ~0.2s`),
  - spring-анимация обновления итоговой суммы,
  - light haptic на периодных и action-кнопках.
