## 1. 🐛 «Не удалось сохранить транзакцию»

Репро владельца: Cashflow → Новый расход → категория «Кв Светлогорск»,
сумма 53 500 RUB, дата 26.08(?), частота «Не повторять», заметка «Перевел Ане»
→ галочка → алерт «Транзакция не сохранена. Проверьте выбранный счёт, дату
и доступный баланс».

Зацепки для диагностики (из аудита данных 2026-08-27,
`thoughts/research/2026-08-27-full-data-audit.md`):
- все 64 `FinanceAccount` указывают на легаси-сущности, ни один на core
  `Account` — если форма расхода валидирует выбранный счёт по этим линкам,
  сохранение может падать на любом счёте;
- 89 `CashflowTransaction` привязаны к легаси-ID; 4 транзакции вовсе без счёта;
- в дампе есть счета с пустым именем и архивные с `includeInTotal=true` —
  picker может подставлять невалидный счёт по умолчанию.

Диагностика: найти точный путь ошибки (какая проверка выдаёт этот алерт),
использовать скилл `millio-forensics` + дамп
`scratchpad/backup-2026-08-27.json`, где уже есть все счета/линки владельца.
На скрине счёт в форме не виден — выяснить, какой счёт был выбран/подставлен.
