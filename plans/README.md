# plans/

**HOW** — технические планы реализации. Один план = одна функция.

## Формат

Имя файла: `YYYY-MM-DD__name.md` (двойное подчёркивание — отличает планы от spec/research). Шаблон: [../templates/plan.md](../templates/plan.md).

## Структура плана

1. **Ссылка на spec** (`specs/YYYY-MM-DD-name.md`)
2. **Challenge Log** — итог 3 вопросов:
   - Решает ли план проблему из spec?
   - Самое ли это эффективное решение (2-3 альтернативы с +/- и обоснованием)?
   - Нет ли кода ради кода?
3. **Фазы** — каждая с acceptance criteria, файлами, статусом `[ ]` / `[x]`
4. **Edge cases** — что обдумано заранее (Think Several Steps Ahead)
5. **Итоговый блок** — реализован целиком / что осталось

## Правила

- Любой агент, работающий по плану, обязан его актуализировать: отмечать фазы `[x]`, дописывать что сделал.
- Перед началом кодинга ждать триггер-фразу `"Реализуй фазу N по плану"` (guard phrase).
- Не пропускать self-audit после фазы — сверяться с acceptance criteria из spec.
- Законченный план → `plans/archive/`.

## Параллельные фазы

Если фазы независимы — можно запускать параллельно в отдельных сессиях Claude Code / терминалах. Проверь зависимости в плане перед параллелизацией.
