# Ручное деление платежа по кредиту (тело / проценты)

**Статус:** отложено владельцем в 2.1 — в релиз 2.0 не входит (решение 08.09.2026).
**Запрос владельца:** «когда вношу платёж, хотелось бы руками менять тело и проценты,
расчётные подставляй сам, чтобы поменять».

## Почему это дёшево

Ядро уже принимает деление явными параметрами — менять его не нужно:
`Core/AccountsCore/Loan/LoanPaymentRecorder.swift:30` —
`recordScheduledPayment(principalPart:interestPart:)`. Правка целиком в UI.

## Что делать

`UI/Services/Finances/AccountsCore/Loan/LoanPaymentConfirmSheet.swift` (108 строк):
три строки-значения (`payment` в шапке, `payment_principal`, `payment_interest`)
становятся редактируемыми полями.

**Поведение — «все три поля свободны»** (выбор владельца):
- правишь любое из трёх — остальные досчитываются;
- изменил общую сумму платежа → разница уходит в **тело долга** (проценты остаются
  расчётными за период);
- изменил проценты → тело = сумма − проценты;
- изменил тело → сумма = тело + проценты (сумма растёт, а не проценты падают).

## Обязательные ограничения

- Денежный ввод — только через `AmountTextField` (глобальное правило проекта,
  raw + display, парсинг разрядов с пробелом).
- Тело > 0, иначе долг не уменьшится — уже есть ошибка
  `accounts_core.loan.detail.error.payment_below_interest`
  (`LoanPaymentError.nonPositivePrincipalPart`), переиспользовать её, новую не заводить.
- Тело не больше остатка долга — в `record` уже стоит `min(entry.principalPart, outstanding)`,
  но в UI это нужно показать до нажатия, а не молча срезать.
- Кнопка «Внести N ₽» пересчитывает подпись под фактическую сумму.
- «Остаток после платежа» пересчитывается вживую.
- Правка не должна ломать пересоздание плановой операции (`syncPlannedPayment`,
  `LoanPlannedPaymentScheduler`) — платёж, внесённый не по графику, всё равно закрывает
  ближайшую плановую строку и планирует следующую.

## Тесты

- Инвариант: тело + проценты == сумме платежа при любом порядке правок.
- Интеграционный: внесение платежа с ручным делением → долг уменьшился ровно на тело,
  `paidInterestTotal` вырос ровно на проценты, плановая строка пересоздана одна.
