# Backlog: race в сидинге данных карточки «Динамика» для App Store скриншотов

**Статус:** НЕ НАЧАТ (backlog, фикс не выполнялся)
**Дата:** 2026-08-15
**Контекст:** обнаружено при попытке добыть скриншот 02-dynamics для App Store (fastlane `capture_screenshots`).

## Что найдено

Карточка «Динамика» (`testScreenshot02Dynamics` в `millioUITests/ScreenshotTests.swift:37`) в
Screenshot Mode (`MILLIO_SCREENSHOT_MODE=1`) при **изолированном** запуске (только этот один
UI-тест, без остальных 7 карточек) стабильно (8/8 попыток подряд, все 4 проверенные комбинации
en-US/ru × iPhone 17 Pro Max) показывает пустое состояние — «No data to display» / «No groups»
(«Нет данных для отображения» / «Нет групп»), баланс 0.

Тест ждёт 6 секунд после перехода на вкладку (`sleep(6)`, ScreenshotTests.swift:47) — по комментарию
в коде это уже усиленный запас против флейков, которых видели «2 прогона подряд». Реальность
оказалась хуже: в изолированном прогоне это не флейк, а **детерминированный** провал 8 из 8.

## Гипотеза причины

`millioApp.swift:174-179` — при `isScreenshotMode` в `.task` вызывается
`ScreenshotDataSeeder.seed(into: container.mainContext)` асинхронно, **параллельно** с рендером UI
(таб-бар появляется почти сразу, `waitForExistence` не ждёт сидирование).

`ScreenshotDataSeeder.seed()` (`millio/Core/App/ScreenshotDataSeeder.swift:39-71`) в конце вызывает
`AccountSnapshotRebuilder.rebuildAllAccounts()` — без него карточка «Динамика» строит график по
`AccountDailySnapshot`, которых ещё нет (см. докстринг резолвера, комментарий в сидере
строки 63-70). Rebuild явно медленный шаг, и весь путь seed→rebuild, судя по всему, стабильно не
укладывается в 6 секунд при холодном изолированном запуске.

При полном прогоне всех 8 карточек (`fastlane capture_screenshots` без `only_testing`) существующие
скриншоты `screenshots/raw/{en-US,ru}/iPhone*-02-dynamics.png` **уже есть в репозитории и валидны**
(это будет видно по содержимому — были получены раньше, не в этой сессии). Открытый вопрос: почему
полный прогон успешнее — либо кумулятивное время (симулятор/CloudKit warm-up к моменту 2-го теста),
либо иной порядок событий. Не исследовано глубоко — не входило в эту задачу.

## Что НЕ делалось

Резолвер (`HistoricalValuationResolver`/`AccountSnapshotRebuilder`) не трогали. Тест
(`ScreenshotTests.swift`) не трогали. Только читали код для диагностики.

## Рекомендация на будущее (не реализовано)

1. Сделать сидинг в Screenshot Mode **синхронным барьером** перед рендером (например, ждать seed
   завершения перед `waitForMainUI`, а не полагаться на фиксированный `sleep`), либо
2. Увеличить `sleep` в `testScreenshot02Dynamics` с явным запасом (проверить эмпирически, сколько
   реально нужно — 6с недостаточно даже в среднем, не только в худшем случае), либо
3. Разобраться, почему полный прогон (`only_testing` без фильтра) успешнее изолированного, и либо
   унифицировать поведение, либо документировать как обязательный способ прогона для карточки 02.

Приоритет — низкий/средний: не блокер релиза, обходится прогоном полного набора скриншотов вместо
изолированного перезапуска одной карточки.
