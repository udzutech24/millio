# Research: Millio 1.9 pre-release audit

- Date: 2026-08-15
- Scope: iOS app and currency widget on `develop`; release 1.9 (10); Backup/Restore, critical flows, localization, technical gates, signing and App Store readiness.
- Reproduction/evidence: baseline commands, focused/full XCTest, simulator/device runs, Release archive/export validation, static audits, and read-only App Store Connect checks. A release is not ready without a real Backup/Restore round-trip.
- Current architecture and constraints: SwiftUI + SwiftData + CloudKit; scoped guest/user stores; CloudKit private snapshots; keychain and passphrase encryption. Existing user changes, including screenshot/release-note work, must remain untouched. Remote mutations, uploads, commits and submissions are forbidden. Code changes require the explicit guard phrase `Реализуй фазу N по плану`.
- Options considered: (1) trust existing docs/tests — rejected as insufficient; (2) local automated audit only — useful but cannot prove production CloudKit/device/App Store state; (3) layered evidence: static + automated + simulator + physical device + read-only remote checks — selected.
- Recommended option and why: layered evidence with explicit `PASS` / `FAIL` / `BLOCKED` / `NOT RUN`; it prevents unknowns from being mislabeled as success.
- Risks and unknowns: production CloudKit schema; TestFlight train/build state; real iCloud account and auth state; device-key portability; destructive restore preconditions; StoreKit sandbox state; privacy-label metadata; physical-device availability.
- Relevant files/tests: `Core/Backup`, `Core/Security`, `Core/Repository`, `Core/Schema`, `UI/Restore`, `UI/Profile/BackupManagementView.swift`, backup and migration XCTest suites, `docs/BACKUP_RESTORE_SCHEMA.md`, `docs/TESTFLIGHT_RELEASE.md`, Fastlane metadata.
