# Research: единый FX snapshot

## Доказательство проблемы

`ConverterViewModel` получает актуальные курсы напрямую из `RateRepository`, а финансовые экраны используют `CurrencyRateService`. У этих путей независимые in-memory и durable-кэши. Поэтому после обновления один экран может пересчитаться по новому набору курсов, пока Analytics продолжает показывать display-cache со старым итогом.

## Варианты

1. Точечно инвалидировать Analytics-cache. Отклонено: это исправляет один экран, но оставляет два источника актуальности.
2. Давать каждому экрану собственный fallback. Отклонено: легко получить гибридный набор пар от разных API.
3. Сделать `CurrencyRateService` владельцем полного активного snapshot. Выбрано: один источник правды, минимальная перестройка существующей архитектуры.

## Решение

- Основной источник: Millio API.
- Fallback для Millio: полный USD-base matrix от ER-API.
- При отсутствии обоих источников: последний полный локальный snapshot.
- Нельзя смешивать пары между источниками внутри одной ревизии.
- Успешная смена snapshot публикует revision; FX-зависимые UI пересчитываются из того же набора.

## Риски и защита

- Старый Analytics display-cache: сохраняет revision и не восстанавливается, если текущая revision иная.
- Сеть недоступна: локальный snapshot остаётся доступен без ожидания таймаута.
- Обновление в нескольких экранах: используется одно уведомление после атомарной замены полного matrix.
- Явно выбранные legacy-источники не становятся fallback для Millio: для штатного пути допускается только Millio → ER-API.
