# Spec: Cashflow Redesign v2 — UI + Architecture

**Date:** 2026-05-09
**Stage:** 2 / Spec
**Research:** [`thoughts/research/2026-05-09-cashflow-redesign-v2.md`](../thoughts/research/2026-05-09-cashflow-redesign-v2.md)

---

## Problem

1. **Архитектура:** `CashflowViewModel` (4598 строк) — God-VM, сложно тестировать и расширять. `CashflowView` (2080 строк) — монолит.
2. **UX навигация:** переключение между расходами и доходами скрыто, неочевидно — пользователь не видит доходы.
3. **Сетка 4 колонки** — слишком плотно, иерархия данных теряется.
4. **Лимиты невидимы** — BudgetCategoryLimit есть в коде, но визуально не присутствуют в сетке.
5. **Добавление транзакции** — friction: нужно несколько тапов чтобы добавить расход в конкретную категорию.
6. **Заголовок избыточен** — "Май 2026" + "01.05–31.05" дублирует информацию.
7. **FAB дублирует** кнопку добавления — два входа для одного действия.
8. **Chart скрыт** в fullScreenCover — пользователь не знает о нём.

---

## Goal

Переработать экран Cashflow: правильная VM/View-архитектура + современный UX, где расходы, доходы, лимиты и динамика видны с первого взгляда.

---

## Scope

### Архитектура

- Разделить `CashflowViewModel` на 3 VM: Main, Categories, History
- Разделить `CashflowView` на 7 компонентов
- Все существующие функции сохраняются, только реструктурируются

### UI/UX

- Сетка категорий: 3 колонки (вместо 4), шире, читаемее
- PageTabView со свайпом: Расходы ↔ Доходы ↔ Все транзакции
- Summary card: сумма потрачено/заработано + прогресс общего лимита
- Per-category limit bars: тонкий прогресс-бар внизу каждой карточки (если лимит задан)
- Inline collapsible chart: bar chart встроен в скролл-вью, не только fullscreen
- Quick entry: тап на категорию → `CashflowQuickEntrySheet` с цифровым полем
- Упрощённый header: убрать дату "01.05–31.05", оставить только "Май 2026"
- Убрать FAB, оставить одну кнопку "+ Добавить" в Quick Actions
- Empty state для нулевого месяца

---

## Non-Goals

- Редизайн `FinanceViewModel` / `FinancesView` — отдельная задача
- Изменение бизнес-логики: суммы, валюты, рекуррентные платежи — только UI/архитектура
- Перевод на Swift Charts (Charts framework) — оставляем кастомный chart
- Изменение модели данных (SwiftData @Model) — не трогаем
- Редизайн `CashflowTransactionsHistoryView` — внутренний экран, вне scope
- Новые категории или изменение категорий

## Acceptance Criteria

### Архитектура
- [ ] AC-A1: `CashflowViewModel.swift` разбит на `CashflowMainViewModel`, `CashflowCategoriesViewModel`, `CashflowHistoryViewModel` — каждый ≤800 строк
- [ ] AC-A2: `CashflowView.swift` разбит на компоненты, главный файл ≤300 строк
- [ ] AC-A3: Все существующие функции (сортировка, фильтры, история, рекуррентные, импорт, бюджеты) работают после рефакторинга
- [ ] AC-A4: `xcodebuild build` — 0 ошибок после каждой фазы

### UI/UX
- [ ] AC-U1: Сетка категорий отображает 3 колонки на всех размерах экрана (SE, 16, 16 Pro Max)
- [ ] AC-U2: Свайп влево/вправо переключает контекст: Расходы → Доходы → Все транзакции. Summary card и сетка обновляются
- [ ] AC-U3: Summary card показывает правильную сумму для текущей вкладки + прогресс лимита если задан
- [ ] AC-U4: Каждая карточка категории отображает тонкий progress bar лимита (если лимит задан для категории). Цвет: normal / warning (70%) / critical (90%) / exceeded (>100%)
- [ ] AC-U5: Chart секция встроена в ScrollView под Summary card, сворачивается тапом на заголовок
- [ ] AC-U6: Тап на карточку категории в режиме "Расходы" или "Доходы" открывает `CashflowQuickEntrySheet` с pre-selected категорией и цифровой клавиатурой
- [ ] AC-U7: Header показывает только "Май 2026" (без "01.05–31.05"), навигация ←→ сохраняется
- [ ] AC-U8: FAB убран, кнопка "+ Добавить" в Quick Actions row открывает полный редактор
- [ ] AC-U9: Empty state отображается когда в месяце 0 транзакций соответствующего типа
- [ ] AC-U10: PRO-гейт на chart сохраняется (`EntitlementPolicy.canUseCashflowChart`)

## Constraints

- **Стек:** SwiftUI, SwiftData, Swift Concurrency. Без сторонних зависимостей.
- **Dark Mode only** — единственная тема
- **Локализация:** все новые строки в `Localizable.xcstrings` (RU/EN/zh-Hans)
- **PRO-гейт:** chart секция — только для PRO (EntitlementPolicy)
- **Производительность:** сетка с 19–30 категориями должна скроллиться плавно (60fps). Lazy loading.
- **Совместимость:** iOS 17+ (SwiftData требует iOS 17)

---

## Edge Cases

- Пользователь без бюджета/лимитов → progress bars не показываются вообще, карточки без них
- Пользователь с кастомными категориями → корректно отображаются в сетке
- Категория скрыта (isHidden в CashflowSystemCategoryOverride) → не показывается в сетке
- Сумма очень большая (>1M) → AmountFormatter обрезает/форматирует корректно
- Месяц без транзакций (нулевой) → EmptyState view вместо сетки с нулями
- Вкладка "Доходы" с нулём категорий → тоже EmptyState
- Quick entry отменяется (swipe down) → без сохранения, без side effects
- Одновременно несколько активных бюджетных планов → показывать текущий (activePlan)
- Chart PRO-гейт: Free пользователь видит заблур / paywall вместо chart
