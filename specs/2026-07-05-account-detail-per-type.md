# Spec: Экран деталей счёта под каждый тип продукта (AccountsCore)

**Date:** 2026-07-05
**Stage:** 2 / Spec
**Research:** контекст-саммари AccountDetailView/AccountBalanceEngine (сессия 2026-07-05); база `millio/Core/AccountsCore/`, спека ядра `specs/2026-07-04-accounts-core.md`
**План:** [`plans/2026-07-05__account-detail-per-type.md`](../plans/2026-07-05__account-detail-per-type.md)

## Problem

Новый `AccountDetailView` (830 строк) — один экран на все 11 пресетов: нет графика (живёт только в легаси `AccountBalanceChartView` с RU-литералами и `Color(hex:)`), нет edit-sheet свойств (имя/мета/includeInTotal не редактируются вообще), actionsRow показывает действия, которые движок игнорирует (ловушка молчаливой потери данных у market/manualAsset), KPI «Мин/Макс/Изменение» бессмысленны для большинства типов.

## Goal

Каждый из 11 пресетов отвечает на свой главный вопрос за 3 секунды — на едином каркасе (один график-компонент, один KPI-ряд, один edit-sheet), различия только конфигурацией per kind.

## Scope

- Общий каркас: `AccountChartSection`, `KPITileRow`, `AccountEditSheet`, per-kind дескриптор actionsRow.
- 11 пресетов + 12-й «Другое» (manualAsset) — секции/настройки/действия/график/KPI/edge cases.
- Только поля, существующие в модели. Политика: **нет поля — нет контрола** (без исключений).

## Non-Goals

- **Кредитная карта** — отдельный экран (statementDay/dueDay/minPayment/graceDays); дебетовый экран эти поля не показывает никогда.
- **FX-перевод** между валютами (всплывал в 3 дизайнах) — отдельная задача, здесь transfer только same-currency.
- **Redenomination guided-флоу** смены валюты — отдельная фаза; здесь валюта везде read-only.
- **Новые поля модели** (iconName/color, favorite, ReminderMeta, cardColor, priceAutoUpdate, доля владения, Cashflow-тумблер вклада) — отдельная фаза после стабилизации V5-схемы.
- Пуш-нотификации; генератор расписания кредита; мультиактивный портфель; бэкфилл истории цен.

## Acceptance Criteria

- [ ] Один компонент графика `AccountChartSection` на все kind (конфиг: стиль линии, периоды, оверлеи, KPI-провайдер); легаси `AccountBalanceChartView` в новый экран не переносится.
- [ ] Один `KPITileRow`, один `AccountEditSheet` (общий скелет + слот kind-секции), один `PriceRevaluationSheet` (E+F), один `PayoffProgressBar` (loan+debt), один `NextDateCard` (dueDate/termEnd/paymentDay), один `StalenessBadge`, один `RevaluationHistoryList` (F).
- [ ] Движок A: ступенчатая линия у всех трёх (карта тоже — события дискретны); периоды 7Д/1М/3М/1Г/Всё; «Потрачено» = Σ expense+fee, **без** transferOut (перекладывание — не трата) — одна формула.
- [ ] actionsRow каждого kind содержит только действия, которые движок реально читает (E: нет income/expense/transfer/adjust; F: только revalue/продажа).
- [ ] Edit-sheet редактирует все backed-поля: Account (name, note, includeInTotal, group — «Группа» у ВСЕХ kind) + своя мета; валюта — read-only строка везде; assetClass — read-only везде.
- [ ] Ни одного контрола без поля в модели; мёртвые тумблеры (remindEnd, autoRollover, payoutDay, insurance, scheduleType-сегмент) не показываются.
- [ ] archivedAt != nil → read-only у ВСЕХ kind: actionsRow и шестерёнка скрыты, бейдж «В архиве», график обрезан датой архива.
- [ ] Redenomination: график/KPI всех kind — по пост-деноминационным значениям из движка (включая Долг и Бизнес).
- [ ] S8-архив для движков E/F не предлагает «перевести остаток» (transfer = вес 0): формулировка «продать всё / закрыть как есть».
- [ ] Токены везде: AppSpacing / `.millio*` / AppColors / AppAnimation, `L(...)`; без RU-литералов, `Color(hex:)`, `Font.system(size:)`.
- [ ] График кэширует серию по `refreshToken`, не реплеит на каждый body.

## Constraints

- **Стек:** SwiftUI + Swift Charts; SwiftData; запись только через `AccountsCoreService`.
- **Производительность:** 1Г/Всё — с опорой на `AccountBalanceSnapshot` (backfill открыт) либо лимит периода 3М до его готовности (см. Open Questions).
- **Схема:** модель не трогаем — параллельно вводится V5; новые поля см. Non-Goals/фаза 7 плана.

## Общий каркас (един для всех типов)

| Блок | Решение |
|------|---------|
| Хедер | Баланс `.millioTitle` + валюта + бейджи (includeInTotal=false, «В архиве», stale/овердрафт); слот сабтайтла per kind (банк ••last4 / тикер / контрагент / нет) |
| `AccountChartSection` | Чипы периодов + линия + drag-точка + слот KPI; конфиг: интерполяция (step/stepEnd), набор периодов, оверлеи (zero-line, лимит-линия, termEnd/dueDate-риска, cost-basis-пунктир, маркеры событий), инверсия знака (loan) |
| `KPITileRow` | 3 плашки, набор метрик per kind; пустое значение = «—», не 0,00 |
| actionsRow | Существующий скролл-каркас; состав/порядок/заголовки — per-kind дескриптор вместо разрастающегося switch |
| historySection | Общая лента; словарь подписей kind(+direction) → labels; sheets из `AccountDetailSheets` переиспользуются |
| `AccountEditSheet` | Шестерёнка в toolbar → Form: имя / группа / includeInTotal / заметка / валюта read-only + слот kind-секции; внизу деструктивная зона «Архивировать» (S8-алерт) |
| Архив | S8-алерт общий; для E/F — без ветки «перевести остаток» |

## Пресеты

### 1. Карта (дебетовая) · kind=.debitCard · движок A

За 3 секунды: сколько доступно (с овердрафтом) и куда уходят деньги.

- **Секции:** «пластиковый» хедер (банк + ••last4, при last4=nil строка скрыта; баланс <0 в пределах overdraftLimit → «Овердрафт −X из Y» с мини-прогрессом, не голый красный); actionsRow (default-ветка A); график; KPI; кэшбэк карты — **за фичефлагом** до моста Cashback→Account; история; edit-sheet.
- **Настройки:** имя · банк (Picker: справочник + «Другой») · last4 (numeric, 4) · овердрафт (Toggle+сумма) · includeInTotal · группа · заметка · валюта read-only. ⚠️ Цвет карты (нужен `CardMeta.cardColor`) и ссылка на кэшбэк (нужен мост Cashback→Account) — не показывать до полей; хедер до тех пор красится детерминированно по банку.
- **Действия:** Пополнить / Расход / Перевод (same-currency) / Скорректировать / Архивировать (S8).
- **График:** ступенчатая линия (единообразно с движком A), периоды 7Д/1М/3М/1Г/Всё; пунктирная нулевая линия при min≈0; штрихованная зона овердрафта 0…−overdraftLimit; ниже −лимита — error.
- **KPI:** Потрачено (Σ expense+fee) · Поступило (Σ income+transferIn+interest+dividend) · Изменение (Δ и %, цвет по знаку).
- **Edge cases:** last4=nil; **bank=nil → bridge даёт .cash — без фикса bridge экран мёртв** (блокер); минус в пределах/сверх овердрафта; минус без овердрафта = красный как сейчас; свежая карта → empty-state; 1Г без снапшотов; перевод при нуле same-currency кандидатов → disabled с причиной; архив ненулевого баланса → S8; archivedAt → read-only; KPI в пост-деноминационных величинах.

### 2. Наличные · kind=.cash · движок A

За 3 секунды: сколько на руках, как утекает, совпадает ли учёт с кошельком (сверка — фишка).

- **Секции:** хедер (без bank/last4 даже если бридж их записал; <0 → красный + «наличных меньше нуля не бывает — пересчитайте»; бейдж «Сверено N дн. назад», warning после порога); действия (Потратить / Перевод / Пересчитать / Пополнить — «Пересчитать» поднят); график; KPI; карточка «Сверка» (дата последнего adjustment, ±X, CTA «Пересчитать» — derived, полей не нужно); история (adjustment = «Сверка ±X», transferIn = «Снятие/перевод с …»); edit-sheet.
- **Настройки:** имя · группа · includeInTotal · заметка · валюта read-only. ⚠️ Иконка/цвет — общее поле Account, до него не показывать. ⚠️ Напоминание о пересчёте — нужен ReminderMeta.
- **Действия:** expense / income / transfer (подсказка «снятие в банкомате = перевод с карты») / «Пересчитать» — `AccountAdjustBalanceSheet` в режиме «фактическая сумма → дельта» / архив (S8) / деноминация в меню ⋯.
- **График:** ступенчатая, 7Д/1М/3М/1Г/Всё; точки на adjustment (моменты сверки); нулевая пунктирная линия при касании нуля.
- **KPI:** Потрачено (только expense+fee, без transferOut) · Изменение (Δ, %) · Сверка («N дн. назад», warning после порога). Мин/Макс убраны.
- **Edge cases:** минус = ошибка учёта (подпись, но не блокировать); бридж-.cash с CardMeta — реквизиты не рендерить; счёт моложе периода → от createdAt; redenomination без ложного скачка; пустая история → placeholder; time-aware архив.
- **Блокер:** пресета «Наличные» в пикере создания нет — .cash возникает только как побочный эффект бриджа.

### 3. Счёт · kind=.bankAccount · движок A

За 3 секунды: сколько на рабочем счёте, куда течёт, не ушёл ли в овердрафт.

- **Секции:** шапка (банк ••last4; при overdraftLimit>0 строка «Доступно: баланс+лимит»; <0 в пределах лимита → warning-бейдж «Овердрафт», сверх/без лимита → error; бейдж «не в общем балансе»); actionsRow (default A); график+KPI; история (переводы с направлением и парным счётом; fxProvisional-пометка); edit-sheet.
- **Настройки:** имя · банк (общий справочник с Картой) · last4 · лимит овердрафта (0 = нет) · includeInTotal · группа · заметка · валюта read-only. Никаких полей кредитки. ⚠️ Иконка/цвет, избранное — без полей не показывать.
- **Действия:** Пополнить / Списание / Изменить баланс / Перевод (disabled с причиной при нуле кандидатов) / Архивировать / Разархивировать.
- **График:** ступенчатая, 7Д/1М/3М/1Г/Всё; нулевая линия + error-заливка ниже нуля; вторая пунктирная на −overdraftLimit; риска redenomination; после archivedAt — обрез.
- **KPI:** Поступления · Списания (Σ expense+fee, без transferOut — единая формула A) · Изменение (Δ, %).
- **Edge cases:** семантика минуса от лимита (смена лимита задним числом перекрашивает прошлое — осознанно); плоская линия одной точки → placeholder; KPI по пересчитанным суммам при redenomination; time-aware архив; фильтрация ввода last4; кэш серии по refreshToken.

### 4. Вклад / накопительный · kind=.deposit · движок B

За 3 секунды: сколько заработал, сколько будет к концу срока после налога, когда следующая выплата.

- **Секции:** хедер (баланс + бейдж «13,51% годовых · капитализация ежемесячно»); прогресс срока (createdAt→termEnd; nil → чип «Накопительный»; termEnd в прошлом → баннер «Срок истёк» + CTA Закрыть/Пролонгировать); график+KPI; «Проценты и налог» (следующее начисление из шедулера; начислено Σ interest ≤ today; прогноз gross/net; налог-оценка DepositTaxCalculator с пояснением «доля этого вклада»; не-RUB → «≈ по курсу»); условия read-only + «Изменить»; история (interest выделены, будущие события шедулера в ленту НЕ попадают).
- **Настройки:** имя · ставка (Decimal; смена = регенерация ТОЛЬКО будущих interest, сноска) · капитализация (Segmented) · срок (Toggle «Бессрочный» + DatePicker) · пополняемый (Toggle) · досрочное закрытие (Toggle + % штрафа; хранится долей 0…1, конвертация на границе) · includeInTotal · группа · заметка · валюта read-only · ссылка на глобальные налоговые настройки. **Вырезано (мёртвые контролы):** remindEnd, autoRollover, payoutDay — шедулер/нотификации их не читают. ⚠️ «Доход вклада в Cashflow» — нужен Bool в DepositMeta (регрессия 2026-06-24).
- **Действия:** Пополнить (top-up warning при allowsTopUp=false) / Снять / Корректировка / Перевод / Закрыть досрочно (превью штрафа; existing flow fee+transfer+архив) / Пролонгировать (только после termEnd; требует мини-спека rollover) / Изменить условия / Архивировать.
- **График:** лестница (step): факт до today сплошным, дальше пунктир до termEnd по уже сгенерированным будущим interest-событиям (бессрочный — горизонт 12 мес); маркеры капитализаций/пополнений; риска termEnd. Периоды: «Срок»/1Г/Всё (срочный), 1М/1Г/Всё (накопительный) — 7Д не нужен.
- **KPI:** Начислено % (Σ interest ≤ today) · Доход к концу срока net (накопительный: «за 12 мес») · Эффективная ставка APY = (1+r/n)^n−1.
- **Edge cases:** termEnd=nil/в прошлом; валюта ≠ RUB; keyRateForYear не задана → «настройте ключевую ставку», не «налог 0»; пропорциональное распределение налога; смена условий не трогает прошлые interest (sourceTransactionID); earlyClosePenalty=nil → штраф 0; микро-ступени после округления .plain; минус через снятие → красный + предупреждение; redenomination; archivedAt read-only; проекция визуально ≠ факт.

### 5. Кредит · kind=.loan · движок C

За 3 секунды: сколько осталось выплатить, когда/сколько следующий платёж, как долг тает.

- **Секции:** хедер «Осталось выплатить» — |баланс| положительным числом, textPrimary (НЕ красный: вечный минус = шум); `PayoffProgressBar` «Погашено N% из principal» (скрыт при principal nil/0); `NextDateCard` «Следующий платёж» (monthlyPayment + дата из paymentDay с клэмпом 29–31; CTA «Оплатить» с префиллом; мягкий бейдж «платёж не отмечен» — не «просрочен»; скрыта при nil/0); график+KPI; условия-грид (пустое/дефолтное → CTA «Указать», rate=0 и termEnd-хардкод не выдавать за правду); история со словарём loan-подписей.
- **Настройки:** имя · ставка (0 → «не указана», не «0%») · ежемесячный платёж · день платежа (Picker 1–31) · дата окончания (Toggle + DatePicker; пресет хардкодит +1 год — дать исправить) · сумма кредита (principal) · includeInTotal (подпись «вычитать долг из net worth») · группа · заметка · валюта read-only. **Вырезано:** «Страховка» (семантика insurance неизвестна), scheduleType-сегмент (меняет только подпись — декоративен без генератора). ⚠️ Напоминание о платеже — нужен ReminderMeta (единое решение с вкладом/долгом).
- **Действия:** Платёж (income, префилл monthlyPayment, primary) / Досрочное погашение (extraPayment) / Оплатить со счёта (transfer) / Проценты·Комиссия (interest/fee — во второй ряд) / Корректировка остатка / Погасить полностью (составное: платёж на остаток → предложение архива) / Архивировать (S8 с loan-wording: «перевести остаток» = финальный платёж).
- **График:** линия |остатка| к нулю; инверсия цвета (вниз = позитив); периоды 1М/6М/1Г/Всё (7Д убран); маркеры платежей; риска termEnd только если срок введён вручную; прогноз-пунктир НЕ рисуем (генератора нет).
- **KPI:** Погашено за период (Σ income+extraPayment+transferIn) · Проценты и комиссии за период (Σ interest+fee; «—» при нуле) · Прогресс погашения % (скрыт без principal). Мин/Макс/Изменение не используются.
- **Edge cases:** rate=0/termEnd-хардкод из пресета; переплата (баланс >0) → «Переплата +X» + подсказка; остаток ≤0.01 → «Кредит выплачен 🎉 Архивировать?»; клэмп paymentDay; monthlyPayment nil; redenomination через движок; валютный кредит (KPI не смешивают валюты); пустая история; archivedAt read-only.

### 6. Долг · kind=.debt · движок D

За 3 секунды: КТО, СКОЛЬКО осталось, КОГДА вернуть — и погасить одной кнопкой.

- **Секции:** хедер — |остаток| (модуль; минус — деталь движка) + фраза-направление «Вы должны Ивану» / «Иван должен вам» + аватар-инициалы (counterparty=nil → «Я должен / Мне должны»; «я должен» НЕ красный — error только для просрочки); статус-чипы (`NextDateCard`-механика: «вернуть до … · осталось N д» / «просрочено N д» error / «без срока»; «под X% годовых» только при rate, без прогнозов); `PayoffProgressBar` «Погашено X из Y · N%» (база |openingBalance|; при ≤0.01 → «Долг закрыт 🎉» + архив); direction-aware actionsRow; график+KPI; история с direction-словарём; edit-sheet.
- **Настройки:** имя · контрагент (TextField + подстановка недавних) · направление (Segmented, **LOCKED после первого не-opening события**, подсказка «создайте встречный долг») · срок (Toggle + DatePicker) · ставка (опционально, справочная) · includeInTotal · группа · заметка · валюта read-only. ⚠️ «Напомнить о сроке» — нужен ReminderMeta (`remindDaysBefore`), без поля не показывать.
- **Действия:** «Вернуть»/«Мне вернули» · «Занять ещё»/«Дать ещё» (по direction) · Погасить полностью (one-tap + предложение архива) · Перевод · Скорректировать · Начислить % (только при rate — шедулера нет, не обещаем) · Архивировать.
- **График:** линия |остатка| к нулю, area к нулевой линии; периоды 1М/3М/1Г/Всё, дефолт «Всё»; пунктирная вертикаль dueDate; цвет линии по direction (owedToMe — positive, owedByMe — нейтраль); error только на чипе просрочки.
- **KPI:** Изначально (|openingBalance|) · Погашено (сумма и %) · До срока N дн / Просрочено N дн (без dueDate — «Изменение за период»). Мин/Макс убраны.
- **Edge cases:** переплата через ноль → direction НЕ флипаем, баннер «переплата X» + «Скорректировать/Оставить»; остаток 0 → celebration; dueDate в прошлом; counterparty=nil (все из пресета/Track C); rate без начислений — чисто справочно; 1–2 события → плоская линия, не пустой canvas; fxProvisional-бейдж; archivedAt read-only; блок смены direction; погашение в другой валюте недоступно (same-currency) → причина + ручное «Вернуть»; **redenomination — по пересчитанным значениям (добавлено по критике полноты)**.

### 7. Инвестиция (брокерский, одна позиция) · kind=.marketInvestment · движок E

За 3 секунды: сколько позиция стоит и в плюсе ли я с учётом всего (дивиденды, комиссии).

- **Секции:** хедер позиции (стоимость qty×price; нереализ. P&L ±сумма/% цветом; чип тикера+класс; `StalenessBadge` свежести цены); график; KPI; «Позиция» (кол-во, средняя цена, текущая цена + источник + «Обновить», стоимость — всё derived); «Результат» (реализ. P&L, Σ дивидендов, Σ комиссий, итог ₽/% — акцент на комиссии); actionsRow; история (dividend/fee с подписью «не влияет на стоимость позиции»; revaluation = «цена обновлена вручную»; redenomination = «сплит/деноминация»).
- **Настройки:** имя · тикер (поиск-пикер; смена при истории — confirm «цены поедут на другой актив») · класс актива **read-only бейдж** (правило Крипты — везде) · includeInTotal · группа · заметка · валюта котировки read-only. ⚠️ Автообновление цены — нужен `MarketMeta.priceAutoUpdate`; до поля режим выводится из наличия провайдера.
- **Действия:** Купить / Продать (при qty→0 предложить архив) / Выплата (dividend; лейбл по assetClass: Дивиденд/Купон; подпись «зачислите на денежный счёт отдельно») / Комиссия (fee) / Указать цену (`PriceRevaluationSheet` — цена за юнит, НЕ AdjustBalance) / Обновить цену (на строке цены) / Архивировать (market-S8: «продать всё / закрыть как есть»). **Убраны:** Перевод, Пополнить/Снять, Изменить баланс (вес 0 в E).
- **График:** стоимость qty(t)×price(t) + пунктир cost basis; область между — цвет по знаку P&L; маркеры ▲buy/▼sell; периоды 7Д/1М/3М/1Г/Всё; до кэша цен — честные ступени по unitPrice сделок + подпись «рыночные цены с {дата}»; сплит — вертикальная метка без разрыва.
- **KPI:** Изменение за период (₽, %) · Вложено (Σbuy−Σsell деньгами) · Общий результат (нереализ.+реализ.+див−комиссии, ₽ и % к вложенному).
- **Edge cases:** qty=0 → «Позиция закрыта · итог +X» + CTA архив; qty<0 → скрыть среднюю/P&L, бейдж; нет провайдера → ручной режим + «Укажите цену»; stale-цена; redenomination — cost basis/средняя ПОСЛЕ множителя; валюта котировки ≠ базовая (fxProvisional); дивиденд не двигает баланс — подписи обязательны; пустой счёт → empty-state «Купить»; смена тикера — confirm; кэш точек графика по refreshToken; **archivedAt → read-only (добавлено по критике полноты)**.

### 8. Акции · kind=.marketInvestment (assetClass=.stock) · движок E

Тот же каркас, что Инвестиция; отличия конфигурацией:

- **Отличия:** хедер — тикер-чип вместо банка; секция «Доход» — дивиденды/комиссии/реализ. P&L; продажа сверх остатка — **жёсткий стоп** (шорт не поддерживаем; у Крипты — мягкое предупреждение); Дивиденд с подсказкой «зачислить на счёт…».
- **Настройки:** как Инвестиция; класс актива read-only. ⚠️ Избранное — без поля Account не показывать.
- **KPI:** Изменение за период · P&L всего (нереализ., к средней) · Дивиденды за период («—» при нуле).
- **Метод cost basis:** один на среднюю цену И realized P&L (avg-cost vs FIFO — открытый вопрос), считается в одном месте.
- **Edge cases:** сверх общих E — выходные биржи (forward-fill = норма, не «нет данных»); период длиннее истории → обрез окна; **archivedAt → read-only (добавлено)**.

### 9. Крипта · kind=.marketInvestment (assetClass=.crypto) · движок E

Тот же каркас; отличия конфигурацией:

- **Отличия:** хедер «0,0345 BTC · 67 250 $/BTC» (точность до 8 знаков, без научной нотации) + дельта 24ч; вместо «Дивиденд» — «Награда», вместо «Комиссия брокера» — «Комиссия сети»; «Обновить цену» заметнее (дырявое покрытие тикеров). **Вырезано в MVP:** чипы-фильтры истории.
- **Настройки:** как Инвестиция; валюта котировки **read-only как у всех** (убран picker «до первой сделки»); класс актива read-only. ⚠️ Источник цены (авто/вручную) — без поля; режим выводится неявно.
- **Награда/комиссия в монетах:** механизм решается **в ядре один раз** (buy@0/sell@0 vs веса dividend/fee в quantity — открытый вопрос), UI трёх market-экранов не расходится. При buy@0 cost basis считать только по buy с unitPrice>0.
- **KPI:** Изменение за период · P&L с покупки · Средняя цена входа (vs текущая).
- **Edge cases:** сверх общих E — микро-количества («<0,01», не «0,00»); токен-своп (redenomination не трогает quantity — только «продать/купить»); конфликт ручной revaluation с авто-апсертом провайдера в тот же dayKey; пустой кэш цен → placeholder «график появится через пару дней»; archivedAt read-only.

### 10. Недвижимость · kind=.manualAsset · движок F

За 3 секунды: сколько стоит объект, рост с покупки, не пора ли обновить оценку; с ипотекой — сколько «своих».

- **Секции:** хедер «Оценка» (стоимость + `StalenessBadge` «Оценка от … · N мес назад», warning после revalReminderMonths, тап → переоценка; заметка = адрес; без cardMeta-веток); ипотека (при linkedLoanID: остаток кредита реплеем C + «Своих: X (Y%)» = оценка − остаток, прогресс-бар, тап → экран кредита); график+KPI; actionsRow (Переоценить primary · Продажа · Настройки · Архив — БЕЗ income/expense/transfer/adjust); `RevaluationHistoryList` (только revaluation + строка «Покупка»; не общая лента); empty-state без переоценок.
- **Настройки:** имя · заметка (placeholder «Адрес») · includeInTotal · напоминание о переоценке (Picker Выкл/3/6/12 мес — поле `revalReminderMonths` есть; v1 питает только in-app бейдж) · связанная ипотека (Picker активных .loan) · группа · валюта read-only. ⚠️ Иконка/фото — общее поле Account, не показывать.
- **Действия:** Переоценить (`PriceRevaluationSheet`, полная стоимость, валидация >0) / Продажа (композит: финальная revaluation → income на денежный счёт → revaluation→0 → архив; атомарность — открытый вопрос) / Настройки / Архивировать (без «перевести остаток»).
- **График:** stepEnd по opening+revaluations, точки-маркеры всегда; пунктир от последней оценки до today (warning при staleness); периоды Год/3 года/Всё, дефолт «Всё»; <2 точек — empty-state.
- **KPI:** С покупки (Δ, %) · Годовых (CAGR; «—» при владении <6 мес) · Оценка (дата + возраст, warning-тинт).
- **Edge cases:** S8 «перевести остаток» не работает для F — заменено; переоценка задним числом/две в день (сортировка date,createdAt,id); переоценка вниз валидна; сумма ≤0 запрещена; висячий/архивный linkedLoanID → секцию скрыть, очистить при сохранении; ипотека в другой валюте → «Своих» только при совпадении валют; redenomination — пост-деноминационные значения; ManualAssetMeta=nil из bridge → ленивое создание меты.

### 11. Бизнес · kind=.manualAsset · движок F

Тот же manualAsset-каркас, что Недвижимость; отличия:

- **Отличия:** сумма подписана «Оценка», не «Баланс»; дефолт напоминания 6 мес (у Недвижимости 12); переоценка в 0 разрешена (обесценился), отрицательная — блок; заметка = метод оценки («по офферу», «×4 прибыли»); действие «Продан/закрыт» = тот же продажа-флоу; helper в шите переоценки «указывайте стоимость вашей доли».
- **Настройки:** имя · напоминание (Выкл/3/6/12) · includeInTotal · группа · заметка · валюта read-only. ⚠️ Доля владения % — нужно поле в ManualAssetMeta, до него только helper-текст.
- **KPI:** С открытия (Δ, %) · Последняя переоценка (дата+давность, warning) · За период (±% по чипу).
- **Edge cases:** как Недвижимость (без ипотеки) + **redenomination — по пересчитанным значениям (добавлено по критике полноты)**; распределения прибыли — см. Open Questions.

### 12. Другое · kind=.manualAsset · движок F (добавлен — был потерян в 11 дизайнах)

Техника, авто, коллекции — любой ручной актив.

- **Каркас:** полностью manualAsset-кит (хедер «Оценка» + StalenessBadge, stepEnd-график, RevaluationHistoryList, PriceRevaluationSheet, продажа-флоу, empty-state). Без ипотечной секции и адрес-плейсхолдера.
- **Настройки:** имя · заметка · includeInTotal · группа · напоминание о переоценке · валюта read-only.
- **Амортизация** (`depreciationRatePerYear`): единственный кандидат на использование поля — именно здесь (не у Недвижимости/Бизнеса); в v1 НЕ показываем, дизайн авто-переоценки вниз — отдельный вопрос владельцу.
- **KPI:** С покупки · Годовых (для дешевеющих активов — отрицательный, валидно) · Оценка (дата+возраст).
- **Edge cases:** = Бизнес (переоценка в 0 разрешена — вещь обесценилась).
