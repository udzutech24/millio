# Spec: Ядро счетов Millio (event-sourcing) — 2026-07-04

**Размер:** L · **Статус:** READY · **Режим:** Bulletproof L, вертикальный срез
**Согласовано владельцем:** event-sourcing = единый источник истины; вклад = отдельный тип `.deposit`; 11 UI-пресетов остаются поверх 6 движков; **без миграции** старых данных.
**Основано на:** `thoughts/research/2026-07-04-accounts-core-rebuild.md`, `plans/2026-07-04__accounts-core-rebuild-plan.md`, аудит `plans/2026-07-02__accounts-system-audit.md`.

---

## Проблема (WHY)

Баланс счёта сегодня имеет двух хозяев — хранимое поле и реплей транзакций. Три экрана считают «одно число» тремя путями (R1). Модель кривая: 3 разнородные сущности (`Card`/`Credit`/`Investment`) + строковая связь `FinanceAccount`; 8 из 11 типов добавления сваливаются в `Investment` (в т.ч. банковский счёт, вклад, долг). Снапшот не связан `@Relationship`, привязка по строке. Следствия: пустой график (BUG#3), расхождение тоталов, плывущие исторические курсы (R4), архив учитывается несогласованно, «удаление» = скрытая архивация.

## Цель (WHAT)

Единое ядро: **любое изменение счёта — событие**; баланс на дату = детерминированный реплей событий. Тотал, дельта, график, снапшот — производные **одной** функции `balanceAt`. Модель — одна сущность `Account` с явным `kind` и настоящими `@Relationship` (каскадное удаление). 11 UI-пресетов → 6 поведенческих движков.

## Контракт

### Сущности
```
Account (@Model)
  id: UUID, name, kind: AccountKind, currency: String
  createdAt, archivedAt: Date?, includeInTotal: Bool
  group: Group?                                   @Relationship(.nullify)
  cardMeta: CardMeta?          // .cash/.debitCard/.bankAccount: bank, last4, creditLimit?
  note: String?                // комментарий — у любого счёта
  depositMeta: DepositMeta?    // .deposit: rate, capitalization, termEnd, payoutDay, allowsTopUp, allowsEarlyClose, earlyClosePenalty?, remindEnd
  loanMeta: LoanMeta?          // .loan: principal, rate, monthlyPayment, paymentDay, termEnd
  debtMeta: DebtMeta?          // .debt: direction (owedToMe/owedByMe), counterparty, dueDate?
  marketMeta: MarketMeta?      // .marketInvestment: symbol, assetClass (stock/crypto/bond/metal)
  manualAssetMeta: ManualAssetMeta? // .manualAsset: note, revalReminder?
  // Полная матрица настроек по 11 продуктам: plans/2026-07-04__accounts-core-rebuild-plan.md §2.7
  // Прогноз вклада/кредита = balanceAt(futureDate) с scheduled interest/payment events (реплей вперёд)
  events: [AccountEvent]     @Relationship(deleteRule: .cascade, inverse: \.account)
  snapshots: [AccountDailySnapshot] @Relationship(deleteRule: .cascade)

AccountEvent (@Model) — ЕДИНСТВЕННАЯ сущность операции (stress-test S1: транзакция Cashflow = это же событие, второй таблицы-леджера НЕТ; категория/бюджеты Cashflow читают события)
  id, account: Account?, date: Date, createdAt: Date, type: EventType
  amount: Decimal?, quantity: Decimal?, unitPrice: Decimal?
  fxRateToBase: Decimal?, categoryID: String?, note: String?
  // Детерминизм реплея (S5): стабильный порядок (date, createdAt, id)
  // Курс/цена на дату без публикации (выходной, S6): последний опубликованный ≤ даты, фиксируется навсегда
  EventType: openingBalance | income | expense | transferOut | transferIn | buy | sell | interest | dividend | fee | extraPayment | rollover | revaluation | adjustment | redenomination
  transferID: UUID?   // связывает две ноги перевода (atomicity-инвариант: Σ переводов = 0)
  originalAmount/originalCurrency?  // если платили в чужой валюте: оригинал + фикс в валюте счёта

Group (@Model)  — только ярлык: name, colorHex, displayCurrency, accounts(.nullify)
```

### AccountKind → движок расчёта (6)
| kind | движок | balanceAt(date) |
|------|--------|-----------------|
| `.cash`, `.debitCard`, `.bankAccount` | A. денежный остаток | opening + Σ(income−expense) ≤date |
| `.deposit` | B. вклад | opening + Σ(income−expense+interest) ≤date |
| `.loan` | C. обязательство | −(Σ выдач − Σ платежей) ≤date |
| `.debt` | C/D. долг | знак по направлению; Σ событий ≤date |
| `.marketInvestment` | E. рыночная | quantity(Σ buy−sell ≤date) × price(date) |
| `.manualAsset` | F. ручной актив | последняя revaluation ≤date |

### 11 UI-пресетов → kind (UI не меняется)
card→.debitCard · account→.bankAccount · deposit→.deposit · credit→.loan · investment→.marketInvestment|.manualAsset (по наличию тикера) · house/business/other→.manualAsset · stocks/crypto→.marketInvestment · debt→.debt. (Наличка — вариант карты без банка, отдельный пресет добавим при желании; сейчас маппится в .cash при пустом банке.)

### Функция истины
`balanceAt(account, date, baseCurrency) -> Decimal` — детерминирована; курс берётся зафиксированный в событии (`fxRateToBase`) или исторический на дату; для рыночных — цена на дату. **Все** потребители (Accounts-тотал, Analytics-тотал/дельта, график, снапшот-кэш) вызывают только её.

### Снапшот — производный кэш, валютно-нейтральный
`AccountDailySnapshot` = кэш `balanceAt` по дням, **в валюте самого счёта** (не в базовой и не в отображаемой). Может быть удалён и пересобран из событий в любой момент. Не источник истины. Конвертация в любую валюту просмотра/отчётности — на чтении: для исторической точки — курс НА ДАТУ точки (замороженный), для сегодня — текущий. Переключение валюты просмотра ничего не пересобирает. Опциональный материализованный слой в primaryCurrency — тоже производная.

### Архив / удаление (чистая семантика, time-aware)
Единый предикат участия — **с датой**: `participates(account, date) = includeInTotal && (archivedAt == nil || date < archivedAt)`. Все потребители (тотал, график, дельта) передают дату точки; «сегодняшний тотал» = participates(today).
**Двухступенчатая защита (решение владельца 2026-07-04): в основном UI разрушительного действия НЕТ.**
- **«Удалить» в основном UI** (единственная кнопка) = на самом деле закрытие/архивация: `archivedAt = now`. **История НЕ меняется задним числом**: точки ДО даты закрытия продолжают включать счёт; с даты закрытия — не участвует («обнуление с сегодня»). Кэш и события сохраняются, новые снапшоты не генерируются. Счёт попадает в «Архив».
- **Экран «Архив»**: два действия — «Восстановить» (снять archivedAt) и «Удалить навсегда» = `modelContext.delete(account)` → каскад events+snapshots, история пересчитывается задним числом ОСОЗНАННО, с предупреждением «сотрётся N операций за M лет, прошлые тоталы пересчитаются». Физическое удаление доступно ТОЛЬКО отсюда — случайно уничтожить историю из основного UI невозможно.
- Удаление группы: счёт остаётся, `group=nil` (Ungrouped показывается явно), закрытые счета в текущий тотал Ungrouped не текут (participates(today)=false).

## Acceptance Criteria

- **AC1.** Изменение баланса/кол-ва/стоимости счёта в UI создаёт `AccountEvent`, а не пишет в хранимое поле напрямую. Хранимый баланс — только кэш, пересчитывается из событий.
- **AC2.** `balanceAt` — единственный источник числа: Accounts-тотал == Analytics-тотал до копейки (нет расхождения 3 ₽).
- **AC3.** График портфеля непрерывен при дырах в снапшотах любого счёта (forward-fill by design через реплей). «No data» только при полном отсутствии истории (0 событий).
- **AC4.** Исторический курс/цена детерминированы: повторное открытие Analytics даёт те же прошлые точки (нет «плывущих» R4).
- **AC5.** Каждый из 6 движков покрыт unit-тестом реплея (opening, приход/расход, %, купля/продажа × цена, переоценка, долг со знаком).
- **AC6.** Закрытие/архивация time-aware: точки графика/тотала ДО archivedAt включают счёт (история неизменна байт-в-байт после архивации), точки ПОСЛЕ и «сегодня» — не включают; снапшоты не генерируются; операция обратима. Тест: архивировать счёт → вчерашняя точка графика не изменилась.
- **AC7.** «Удалить» из основного UI = архивация (никогда не destructive); физическое удаление доступно только из экрана «Архив» с предупреждением (N операций / M лет); каскад стирает events+snapshots; Ungrouped не уходит в необъяснимый минус.
- **AC8.** Снапшот-кэш пересобираем из событий одной командой; результат идентичен прямому реплею.
- **AC9.** Нигде в кодовой базе вне ядра реплея нет прямой мутации баланса (`balance +=` и т.п.) — проверяется grep-гейтом; расход НЕ обрезается `max(0,…)` молча.
- **AC10.** Курс/цена, использованные в событии или закрытой точке кэша, встроены в запись и не перезапрашиваются (append-only для использованных дат); повторное открытие экрана даёт байт-в-байт те же исторические точки.
- **AC11.** Смена валюты счёта = событие `redenomination` с зафиксированным курсом; события до него не переписываются; `balanceAt` кусочно-непрерывен через дату редоминации.
- **AC12.** Перевод между счетами — две ноги с общим `transferID`, создаются атомарно; системный инвариант «Σ всех переводов = 0» покрыт тестом.
- **AC13.** Переключение валюты просмотра: исторические точки конвертируются курсом на СВОЮ дату (не сегодняшним); счёт в валюте просмотра показывается без конвертации; переключение не пересобирает кэш и не пишет в хранилище (тест: ₽→$→₽ даёт исходные числа байт-в-байт).
- **AC14.** Смена ОСНОВНОЙ валюты приложения (primaryCurrency): не пишет в хранилище ни байта (события и кэш неизменны); тотал/дельта/график/Credit-Debit проецируются в новую валюту (история — курсами своих дат); операция полностью обратима байт-в-байт. Налоговый лимит по вкладам считается в ₽ независимо от primaryCurrency.
- **AC15.** Смена валюты СЧЁТА = событие redenomination (AC11) — покрыта тестом «график счёта непрерывен через дату смены, скачка на курсе нет; события до смены не изменены».

Полный stress-анализ рисков (Т1–Т9, П1–П4): `plans/2026-07-04__accounts-core-rebuild-plan.md`, раздел 6.

## Scope
**В скоуп (по фазам плана):** новая модель Account/AccountEvent/Group; `balanceAt`; единый TotalsService; снапшот-кэш как производная; движки A→C→B→E/F; архив/удаление/группы; миграция 11 пресетов; снос Card/Credit/Investment/FinanceAccount.
**Вне скоупа:** миграция реальных пользовательских данных (отдельная задача после стабилизации); редизайн UI добавления (11 пресетов остаются); Cashflow-транзакции как отдельная фича (интегрируются как источник income/expense-событий, но их экран не переписываем).

## Non-Goals
- Не сохранять двойной источник баланса «на переходный период» — это и есть баг.
- Не мигрировать старые снапшоты — пересобираем.
- Не трогать backup/restore-схему в этой итерации (адаптируем после ядра).

## Риски
| Риск | Митигация |
|------|-----------|
| Реплей медленный на длинной истории | снапшот-кэш + инкрементальный реплей от последнего снапшота |
| Рыночная цена/курс недоступны (auth error) | последняя известная цена; счёт не выпадает из тотала |
| Большой объём — регресс существующего | вертикальный срез по фазам, /stress-test каждой, fallback-ветка |
| Cashflow-транзакции завязаны на старые cardID/creditID/investmentID | адаптер: старые ссылки → account.id + income/expense events |
