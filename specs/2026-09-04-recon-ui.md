# Разведка UI: экраны нового типа счёта «Кредит» (часть Б)

Дата: 2026-09-04
Цель: найти переиспользуемые компоненты вклада для экранов кредита (деталка, условия, график платежей, досрочное погашение), не копируя код.

## 1. Вклад как образец

**Деталка счёта (все типы, включая вклад)** — единый мега-экран, не отдельный файл на тип:
- `millio/UI/Services/Finances/AccountsCore/AccountDetailView.swift` (1632 строки). Ветвление по типу через computed-свойства (`depositPresentation`, `investmentPresentation`, `account.productType == .creditCard`) и `enum ActiveSheet` (строка 31, кейсы: `.income .expense .adjustBalance .editDetails .transfer .earlyClose .depositTopUp .depositAdjustBalance .depositTerms .depositMaturity .buy .sell .dividend .fee .refund .revalue`) + `sheetContent(for:)` switch (строка 1084). Для нового типа «Кредит» — добавить кейсы в этот же enum и ветки в `sheetContent`, отдельный файл экрана заводить не нужно.
- Hero вклада — не отдельный вид, а `customContent` в общем `AccountHeroCardView` (см. п.2): AccountDetailView.swift:247-256.
- Секция под hero — `DepositDetailSection` (кнопки действий + налоговая плашка): `millio/UI/Services/Finances/AccountsCore/Deposit/DepositDetailSection.swift:265` (вызов в AccountDetailView.swift:266-270).
- Открытие меню «···» вклада — bottom sheet вместо системного `Menu`: `showDepositActionsSheet` (AccountDetailView.swift:26, 294-296, 321-328).

**Форма условий вклада** — общий `DepositTermsInputCard` встроен в ДВЕ оболочки:
- Создание: `millio/UI/Services/Finances/AccountsCore/InlineDepositCreateForm.swift` — инлайн-секция внутри общего «Добавить счёт» (вызывается из `FinanceAddAccountView.swift:526`), не отдельный экран.
- Правка условий: `DepositTermsEditSheet` в `millio/UI/Services/Finances/AccountsCore/Deposit/DepositOperationSheets.swift:190` — системный `Form`+`NavigationStack` (старый язык, НЕ тёмные боксы).
- Общая карточка полей: `millio/UI/Services/Finances/AccountsCore/Deposit/DepositTermsInputCard.swift:8` — сумма/ставка/периодичность/чипсы/тумблеры, используется из обоих (DepositOperationSheets.swift:277, InlineDepositCreateForm.swift:75).

**«Реквизиты счёта»** — новый тёмный язык (Коммит 2), сливает генерик-поля счёта и условия вклада в один лист:
- `millio/UI/Services/Finances/AccountsCore/Deposit/DepositAccountDetailsSheet.swift:134` (`DepositAccountDetailsSheet`). Открывается через `ActiveSheet.editDetails` (AccountDetailView.swift:1147-1150) — ветка `if account.kind == .deposit`, для кредитки там же ниже отдельная ветка `CreditCardEditSheet` (system Form, старый язык).
- В этом же файле — переиспользуемые примитивы нового языка: `AccountDetailsBoxCard` (:8, тёмная плашка вместо `Form`), `AccountDetailsFieldRow` (:33, строка-chevron → bottom-sheet пикер), `AccountDetailsToggleRow` (:62), `AccountFieldPickerSheet` (:86, обёртка «заголовок + Готово» для любого пикера, `.presentationDetents([.medium])`).

**Навигация:** `AccountDetailView` открывается `NavigationLink` из списка счетов — `FinancesView.swift:1055`, `FinanceRows.swift:370`, `CashflowUnifiedUpcomingView.swift:87`, `ArchivedAccountsView.swift:110`.

**Стейт:** НЕТ отдельного `ViewModel`-класса ни у деталки, ни у форм — везде plain `@State` внутри `View`-структур (AccountDetailView.swift:13-29; DepositTermsEditSheet — @State-поля инициализируются в `init` из модели). Запись — только через сервисный слой: `AccountsCoreService` (мутации баланса/архивации) и `DepositOperationCoordinator.editTerms` (пересборка графика начислений вклада). Компонент нигде не хранит ссылку на `FinanceViewModel` — обновление списка идёт через `EventBus.shared.publish(...)`.

## 2. `AccountHeroCardView`

Файл: `millio/UI/Services/Finances/AccountsCore/Hero/AccountHeroCardView.swift`.

- `AccountHeroPresentation` (:7) — value-модель: `name`, `subtitle` (банк/•• last4), `typeTitle` (капсула справа), `amountText`+`currencySymbol` (готовая строка, не число), `isNegative` (красит сумму в `AppColors.error`), `iconName/iconColorHex/fallbackIconName`, `gradientHexes`, **`detailLines: [String]`** (произвольные строки-подробности под суммой) и **`badges: [Badge]`** (переносящиеся капсулы-статусы, `isWarning` красит в `AppColors.warning`).
- `AccountHeroCardView<Content>` (:93) — носитель (градиент/скругления/паддинг) ОБЩИЙ для всех типов; init без замены даёт `standardContent` (identity-строка + сумма + detailLines + badges), либо `init(presentation:customContent:)` (:105) полностью подменяет начинку — так делает вклад (`DepositHeroContent`) и инвестиции (`InvestmentHeroContent`), сохраняя общий градиентный носитель.
- **Готового прогресс-бара НЕТ.** `detailLines`/`badges` — только текст. Прогресс-бар «Осталось выплатить» кредита нужно рисовать в `customContent`, как это уже сделано у вклада (см. п.6).
- Крупная цифра — своя, не параметризуема отдельно: часть либо `standardContent.amountRow` (:201), либо целиком кастомного контента.

Вывод: для кредита — свой `CreditHeroContent` через `customContent`, по образцу `DepositHeroContent`; сам `AccountHeroCardView` не трогать.

## 3. `AccountActionsSheet` + паттерн bottom sheet

Файл: `millio/UI/Services/Finances/AccountsCore/AccountActionsSheet.swift`.

- `AccountActionSheetItem` (:5): `title`, `subtitle?` (серым, для предупреждений), `icon`, `isDestructive`, `action`.
- `AccountActionsSheet` (:17): принимает `accountName`, `accountTypeTitle`, `items: [AccountActionSheetItem]`, `onDismiss`. Высота листа **вычисляется по числу пунктов** (:25-31, `.presentationDetents([.height(sheetHeight)])`) — не системный `.medium/.large`.
- Единственное использование — `AccountDetailView.swift:323` (пункты собирает `depositActionSheetItems(_:)`, :1516).

**Общий паттерн bottom sheet в проекте — ДВА конкурирующих языка:**
1. Новый («тёмный», Коммит 1-2): свой `View`-контейнер + `.presentationDetents([.height(N)])` или `[.medium]`, ручка `.presentationDragIndicator(.visible)`, кнопка «Готово» вместо toolbar. Так сделаны `AccountActionsSheet`, `AccountFieldPickerSheet`, `DepositAccountDetailsSheet`.
2. Старый: системный `Form` внутри `NavigationStack`, `.toolbar` с `.cancellationAction`/`.confirmationAction`. Так сделаны `DepositTopUpSheet`, `DepositCloseSheet`, `DepositBalanceAdjustmentSheet`, `DepositTermsEditSheet` (все — `DepositOperationSheets.swift`).

Для кредита мокап («деталка + 3 листа») ближе к языку (1) — но операционные листы (пополнение/списание и т.п. аналоги) в проекте по вкладу пока живут в языке (2). Явного единого чек-листа «когда какой» в коде нет — решение по новому экрану принимать по мокапу, не по прецеденту.

## 4. `AmountTextField`

Файл: `millio/UI/Shared/AmountTextField.swift` (79 строк, полностью прочитан).

```swift
struct AmountTextField: View {
    let placeholder: String
    @Binding var value: String                 // канонический raw, "." разделитель, без разрядов
    var maxFractionDigits: Int = AmountInputFormatter.defaultFractionDigits
    var font: ((String) -> Font)? = nil         // шрифт как функция от текущего display-текста
}
```
Раздельные raw (naружу, `Binding<String>`) / display (внутри, `@State`) — синхронизация в `onChange`, реассайн только при реальном отличии (курсор не прыгает). Статики `AmountTextField.canonical(from:)` / `.formatted(from:)` — чистые функции, переиспользуются вне поля (пример: `DepositTermsInputCard.swift` — форматирование `incomeHint`).

Пример использования с динамическим шрифтом (для крупного ввода в bottom sheet — то, что нужно для «Досрочного погашения»):
`DepositAccountDetailsSheet.swift:540` —
```swift
AmountTextField(placeholder: "0", value: $rateText)
    .font(.millioTitle)
    .focused($inputFocused)
```

## 5. UI-токены

- `millio/UI/Design/AppSpacing.swift` (12 строк) — `xs=4 s=8 m=12 ml=14 l=16 xl=20 xxl=24 xxxl=32`.
- `millio/UI/Design/AppTypography.swift` (40 строк) — шкала `millioDisplay/Title/Headline/Subheadline/Body/Callout/Caption/Micro`, у каждой Regular/Medium/Semibold/Bold варианты по месту.
- `millio/UI/Design/AppColors.swift` (192 строки) — **роли ЕСТЬ, но без слова «accent» как отдельного токена**:
  - `brandPrimary` = `RGB(104,165,255)` (~`#68A5FF`, голубой) — фактическая роль «accent» (используется в чипсах/сегментах/кнопке «Готово»).
  - success/зелёный: `positiveColor = #18C57A`, `toggleOnGreen = #34C759` (для `Toggle.tint`), `incomeActionGradient = [#1EE688, #18C57A]`.
  - danger/красный: `error = Color.red` (системный, не hex!), `negativeColor = #FF5E5E`, `expenseActionGradient = [#FF7070, #FF4444]`.
  - dim: `textSecondary`/`textTertiary` = `Color.white.opacity(0.7)` (тёмная тема — единственная).
  - warning (не danger) = `Color.orange`.
  - Отдельная категория «Card Box» под тёмный язык Реквизитов: `cardBoxBackground = #131316`, `cardBoxBorder = #202024` (:176-182) — это и есть подложка новых боксов формы.

**Сопоставление с мокапом:**
| Мокап | Ближайший существующий | Вывод |
|---|---|---|
| Медь `#E0A458` | нет ни одного близкого (ближайший `profileIconOrange #FF9F0A` — не медь, слишком яркий и жёлтый) | **новый токен нужен**, напр. `creditAccentCopper` |
| Зелёный `#4FBF8B` (тело долга) | `positiveColor #18C57A` — более насыщенный/ярче | можно переиспользовать `positiveColor` без потери смысла (роль совпадает — «хорошая» часть долга), либо завести приглушённый вариант под двухцветную полосу |
| Красный `#E4685D` (проценты) | `negativeColor #FF5E5E` / `error` (системный красный) — оба ярче | то же: переиспользовать `negativeColor` для полосы допустимо, точный hex мокапа не заведён |

Рекомендация: не плодить токены под один экран — завести `creditAccentCopper` (единственного явно отсутствующего цвета) в `AppColors.swift`, для зелёного/красного полосы взять `positiveColor`/`negativeColor` как есть (расхождение в оттенке минимальное, разные токены ради 1 хекса — оверинжиниринг).

## 8. Дыры — чего нет и придётся писать с нуля

1. **Двухцветная полоса-стек «тело/проценты»** — есть только одноцветный `progressBar` (`DepositDetailSection.swift:100`) и нативный `ProgressView` (`CreditCardDetailSection.swift:56`). Нужен новый компонент: тот же `GeometryReader`+`Capsule`-паттерн, но с двумя сегментами разной ширины/цвета.
2. **Радио-строка с цифрой выгоды** («срок» vs «платёж» в bottom sheet досрочного погашения) — компонента нет вообще, ни как переиспользуемого блока, ни как одноразового решения в другом месте.
3. **Диф-таблица «было → стало»** — ближайший аналог, `DepositCloseSheet.row(_:_:)` (`DepositOperationSheets.swift:105`), рисует ОДНУ колонку значений в системном `Form`, не две колонки с сравнением. Писать с нуля, тёмным языком боксов (`AccountDetailsBoxCard`), не системным `Form`.
4. **Крупный ввод суммы в bottom sheet с кастомным шрифтом** — паттерн есть (`AmountTextField` + `.font(.millioTitle)`, п.4), компонент готов, просто применить.
5. **Сегмент «Аннуитетный/Дифференцированный» и чипсы периодичности (5 вариантов)** — сегмент нативный (`.pickerStyle(.segmented)`, готов), чипсы — по образцу `periodChip` (готов, `DepositTermsInputCard.swift:226`), но САМИХ вариантов периодичности кредита (5 штук, не те же 4 что у вклада) в enum'ах нет — заводить новый тип/case-лист.
6. **Экран/список «График платежей»** отдельным файлом не существует. Есть только расчётная бизнес-логика в легаси-слое (НЕ AccountsCore, для сверки/переиспользования алгоритма): `millio/UI/Services/Credits/CreditViewModel.swift` — `CreditState.calculateNewTermAfterEarlyPayment` (:354), `calculateNewPaymentAfterEarlyPayment` (:388), `applyEarlyPayment(amount:reduceTerm:)` (:459) — старый (pre-AccountsCore) расчёт досрочного погашения кредита с уже реализованным выбором «сократить срок / уменьшить платёж». Стоит свериться с формулами, но НЕ встраивать легаси-модель `Credit` — новый тип идёт через `AccountsCore`/`Account`, как вклад.
7. **Ни одного готового `AccountDepositCapitalization`-аналога для кредита нет** — модель условий кредита (сумма/ставка/срок/дата первого платежа/тип платежа/периодичность/ручной платёж) целиком новая, `DepositMeta`/`AccountDepositCapitalization` — только референс по форме, не переиспользуемый тип.
8. **Тёмный toolbar-паттерн `···`→bottom sheet** для кредита нужно завести отдельной веткой в `AccountDetailView.toolbar` (сейчас условие `if let presentation = depositPresentation ... else if account.productType == .creditCard { Menu {...} }` — AccountDetailView.swift:284-311 — второе легаси-меню системное, не bottom sheet; для нового типа кредита правильный образец — ветка вклада, не ветка `.creditCard`).
