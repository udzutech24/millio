# Уведомление о применённых плановых операциях

Статус: **СПЕКА ЗАКРЫТА, ждёт разрешения на код**. Автор запроса — владелец, 2026-09-05.
Research: агент-разведчик 2026-09-05 (первичный) + `millio-audit` 2026-09-05 (откат баланса).

## Проблема

Запланированные доходы и расходы применяются молча. Владелец: «приходит и непонятно, что
обновилось». Баланс счёта меняется без единого следа в интерфейсе — пользователь видит другую
цифру и не знает, почему. Для приложения про личные финансы это подрыв доверия к числу на экране.

Второе: иногда владелец уже обновил остаток вручную (посмотрел в банке и вписал), а приложение
следом применяет плановую операцию — начисление задваивается. Нужен способ отказаться.

## Решения владельца (зафиксированы 2026-09-05)

1. **Сводка при входе в приложение**, а не плашка на каждую операцию.
   Формат: «Пока вас не было: 3 начисления на +86 135 ₽» с раскрытием списка.
2. **Первая версия — БЕЗ кнопки отката.** Решение принято 2026-09-05 после разведки: честного
   отката в коде нет (см. «Откат: чего нет»). Отказ в V1 = владелец удаляет операцию штатным
   способом, как делает и сейчас. Кнопка «я уже обновлял вручную» — отдельная задача после
   починки `applyAccountBalanceEffect`.
3. Красиво, с анимацией. Отдельно выбрано: применить в этой сводке «ультракод»-эффект —
   дизеринг-градиент + haptic (см. «Визуальный эффект»).

## Как устроено сейчас (research)

Применение живёт в `CashflowViewModel.loadTransactions()`
(`millio/UI/Services/Cashflow/CashflowViewModel.swift:405-410`). Срабатывает **при каждом
открытии/пересоздании экрана Cashflow**, не при запуске приложения; фонового таймера нет.

Оттуда стартуют ТРИ независимых процесса:

| Процесс | Где | Что делает с балансом |
|---|---|---|
| Разовые плановые к дате | `CashflowScheduledService.swift:358-416` | `applyAccountBalanceEffect(direction: .apply)`, ставит `hasAppliedBalanceEffect` |
| Повторяющиеся («Ежемесячная операция») | `CashflowScheduledService.swift:252-355` | штампует транзакцию + `applyRecurringTransactionToCardBalance` (`CashflowPersistenceService.swift:537-567`) |
| Проценты по вкладу | `AccountsCoreDepositCashflowBridge.swift:79-148` | **баланс НЕ трогает** — он уже изменён `AccountEvent(.interest)`; мост лишь материализует событие как транзакцию для видимости |

Уведомления после применения нет вообще. Существующий `NotificationManager
.scheduleCashflowScheduledReminders` (`Core/Notifications/NotificationManager.swift:142-182`) —
это системный push ДО даты, другая история.

Точка активации приложения существует: `millioApp.swift:207` (`didBecomeActiveNotification`) —
уже дёргает subscription refresh, widget sync, биометрику, входящие операции.

## Откат: чего нет (разведка `millio-audit`, 2026-09-05)

`CardBalanceEffectDirection { apply, revert }` — `CashflowPersistenceService.swift:14-17`,
метод `:569`. **Вердикт: настоящего отката применённой плановой операции нет.** Детали:

| Дыра | Где | Последствие |
|---|---|---|
| Из планового пути `.revert` не вызывается никогда | call sites `:253` (read-only), `:365` (редактирование), `:840` (удаление) | откат придётся писать с нуля |
| core-`Account`: и apply, и revert — no-op | `cardProvider :583` → легаси `card(for:)` (`CashflowViewModel.swift:154`) | на новых счетах кнопка молча ничего не сделает |
| Неидемпотентность | guard `:577` → `persistedBalanceEffectWasApplied :772-785` (для корректировок всегда `true`) | второй revert подряд вычтет повторно |
| Клэмп `max(0,…)` | `:604`, `:561` | apply потерял величину, revert вернёт полную → **завышение баланса** |
| FX-асимметрия recurring | apply по текущему курсу `:555`, revert по историческому `:669-674` | дрейф суммы |
| Нет поля «отказано пользователем» | `CashflowTransaction.swift:794` — единственный флаг | откатили → следующее открытие Cashflow применит заново |
| Чекпойнт откатывается назад | `:364` `min(stored, referenceNow)` | сдвиг часов / восстановление бэкапа → повторное применение |
| Проценты по вкладу | `AccountsCoreDepositCashflowBridge` | ни revert, ни delete не существуют |
| Тестов на откат плановой операции нет | есть только на revert при удалении легаси `Card` (`millioTests/UI/Services/Cashflow/CashflowViewModelTests.swift:2688, 2891, 3444, 3488`) | |

Единственный честный существующий путь — `deleteTransactionAsync(_:recalculate:)`
(`CashflowPersistenceService.swift:115-178`), тот же, которым владелец удаляет транзакцию руками.
Именно на нём строится будущая кнопка отказа — но только после закрытия дыр выше.

## Архитектурные решения

### 1. Триггер: применение не трогаем, добавляем журнал

Применение остаётся там, где есть (открытие Cashflow). Точки применения дописывают запись в
журнал непоказанных событий. Сводка показывается, когда в журнале есть непоказанные записи, и
проверяется в ДВУХ местах одной и той же функцией:

- **сразу после цикла применения**, если приложение активно (иначе владелец, открывший Cashflow
  и не сворачивавший приложение, сводку не увидит вовсе — дыра чистого `didBecomeActive`);
- **на `didBecomeActive`** (`millioApp.swift:207`) — покрывает случай «применилось и свернул».

Показ забирает записи из журнала (take), поэтому повторный вход сводку не воспроизводит.

### 2. Хранилище журнала: UserDefaults, НЕ SwiftData

Новая `@Model`-сущность сдвинула бы checksum схемы задним числом — известный класс отказа
(сторы не открываются, ошибка 134504). Журнал маленький и эфемерный: живёт от применения до
показа. Хранить `[Codable]` в UserDefaults.

**Ключ обязательно per-scope**, по образцу `GroupsMigrator.swift:46,60-66` (`scopeIdentifier`,
`DataScope.swift:15-22`). Иначе повторим утечку гостевого режима — гость увидит сводку владельца.

### 3. Проценты по вкладу — информационно

Для них баланс двигает `AccountEvent`, отката нет вовсе. В сводке показываются, помечены как
информационные, действий не предлагают.

### 4. Подача: лист снизу, не тост

`ToastCenter` умеет только `show(message:duration:)` — простой текст (`ToastCenter.swift:12-26`),
раскрывающийся список туда не помещается. Берём лист снизу — совпадает с правилом владельца
«меню и подтверждения под большим пальцем». `ToastCenter` не трогаем, третий механизм не заводим.

### 5. Визуальный эффект

По выбору владельца 2026-09-05: появление сводки оформляется «ультракод»-эффектом из Claude Code —
дизеринг-градиент (пиксельная шахматка поверх фиолетового) + haptic. Реализация: `.colorEffect`
с Metal-шейдером + `.sensoryFeedback`; анимации только через `AppAnimation`, отступы через
`AppSpacing`. Обязательно уважать Reduce Motion.

Эффект держится на редкости — применяется ТОЛЬКО здесь, по дашборду не размножается.

## Критерии готовности

- После применения плановых операций показывается сводка с числом операций и суммой; раскрывается
  в список с названием, счётом и суммой каждой.
- Сводка показывается один раз — повторный вход её не воспроизводит.
- Сводка появляется и в сценарии «открыл Cashflow, приложение не сворачивал», и в сценарии
  «применилось и свернул приложение».
- Проценты по вкладу видны в сводке, помечены как информационные.
- Ничего не показывается, если применять было нечего — пустая сводка не всплывает.
- Гостевой режим не видит записей владельца (per-scope ключ, тест).
- Арифметика применения не изменилась: существующие тесты Cashflow зелёные.
- Анимация появления на уровне остального приложения; при Reduce Motion — без эффекта.

## Риски

- **Пишем в денежный путь.** Сама арифметика не меняется, но код журналирования встраивается в
  `CashflowScheduledService` и мост вкладов. Ошибка там = сломанное применение. Гейт каждой фазы —
  зелёные существующие тесты Cashflow.
- Схема SwiftData не трогается сознательно (см. решение 2) — если план начнёт склоняться к новой
  `@Model`, это красный флаг, вернуться к этому решению.
- `CashflowViewModel` — 4598 строк. Новую логику класть отдельным сервисом, не наращивать God-VM.

## Не входит в первую версию

- **Кнопка отказа / откат баланса** — отдельная задача, требует сначала починить
  `applyAccountBalanceEffect` (5 дыр из таблицы выше) + флаг «отказано» в модели.
- Глобальный тумблер в настройках.
- Системные push-уведомления о факте применения.
- Массовый откат нескольких операций одним действием.
