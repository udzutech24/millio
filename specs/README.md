# specs/

**WHAT и WHY** каждой фичи. Контракт с самим собой: что именно делаем и зачем.

## Формат

Один файл = одна фича. Имя: `YYYY-MM-DD-name.md`.

Шаблон: [../templates/spec.md](../templates/spec.md).

## Разделы

- **Problem** — что болит
- **Goal** — что должно стать
- **Scope** — что входит
- **Non-Goals** — что НЕ входит (явно)
- **Acceptance Criteria** — проверяемые критерии готовности
- **Constraints** — ограничения (время, стек, безопасность)

## Правила

- Spec = WHAT и WHY. **Не HOW** — это в `plans/`.
- Spec = контракт. При self-audit и impact analysis сверяешься с ним.
- Для задач размера S (багфикс, 1-2 файла) spec можно пропустить.
- При изменении scope — обнови spec и пересмотри соответствующий план.
