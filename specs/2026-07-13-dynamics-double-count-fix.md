# Spec — фикс двойного учёта в графике «Динамика»

Дата: 2026-07-13 · Статус: НЕ НАЧАТ · Размер: M (Standard)
Research: `thoughts/research/2026-07-13-dynamics-double-count.md`

## Problem

На дне миграции 6b мигрированный вклад (легаси-предшественник + core-двойник)
учитывается в тотале «Динамики» дважды: легаси включён инклюзивно по `date <= archivedAt`,
core включён через opening-снапшот, датированный тем же днём. Окна владения пересекаются
на 1 календарный день. Симптомы: завышенный тултип на дне миграции, «+∞%» на 1W из-за
искажённой домиграционной базы, расхождение заголовок/график/таблица.

## Goal

Один и тот же тотал на любую дату независимо от периода и пути расчёта; никакого двойного
учёта на границе миграции; near-zero база не даёт «+∞%».

## Scope

- `FinanceDynamicsViewModel.swift`: граница легаси-предшественника (day-granularity cutoff),
  консистентность заголовок/график/таблица через единую точку.
- `FinanceAmountText.swift` (или место рендера дельты): UI-фолбок для near-zero базы.
- `Localizable.xcstrings`: ключ «н/д» (RU/EN/zh-Hans).
- `millioTests/`: unit-тест на граничный день + near-zero базу.

## Non-Goals

- НЕ трогаем `AccountsTotalsService`/генерацию снапшотов/`Account.participates`.
- НЕ меняем глобальный `isLegacyActiveInTotal` (обычные архивные легаси-счета).
- НЕ меняем scope-семантику `.currentVisible` vs `.historicalInterval` (только проверяем
  согласованность на историческую дату).
- НЕ трогаем снос легаси (6b Ф5c/Ф6).

## Acceptance Criteria

- **AC1.** Любая дата → ОДИН тотал независимо от периода/пути: заголовок == первая/последняя
  точка графика == сумма строк таблицы (в пределах округления валюты).
- **AC2.** На дне миграции мигрированный вклад учтён РОВНО один раз (легаси владеет днями
  строго до `archivedAt`; core — днём миграции и далее; на границе непрерывно, без разрыва).
- **AC3.** Near-zero база (`|start| < 0.01`) не рендерит «+∞%»: показывается явный фолбек
  «н/д» (локализованный), не число и не «∞».
- **AC4.** Unit-тест воспроизводит старое поведение (double-count на дне миграции) и
  подтверждает фикс; отдельный тест на near-zero базу → фолбек.
- **AC5.** Регрессия: обычные архивные легаси-счета (без миграции) в тотале не меняют
  поведение; домиграционные и постмиграционные дни без изменений.

## Constraints

- Offline-first, `@MainActor`, async/await.
- UI-токены (AppTypography/AppSpacing/AppColors), локализация через xcstrings.
- Day-granularity через `AccountEvent.dayKey` (единая конвенция дня в проекте).
- 1 реальный пользователь (сам владелец), бэкап есть — калибровка риска соответствующая,
  тестовая дисциплина сохраняется.

## Риски

- Смещение границы на 1 день не в ту сторону → gap (недосчёт) вместо overlap. Митигируется
  тестом непрерывности на переходе archivedAt-1 / archivedAt / archivedAt+1.
- Рендер-фолбок «н/д» может конфликтовать с логикой скрытия сумм (`isHidden`) — сохранить
  маскирование при hidden.
