# Баг: одноразовый флаг легаси-миграции переживает замену стора → «счета пропали» навсегда

**Дата:** 2026-07-11 · **Статус:** ДОКАЗАН (эксперимент на симуляторе) · **Фикс:** отдельная задача, НЕ в скоупе 5c.7.6

## Симптом
«Счета» — пустое состояние, тотал шапки/Дашборда 0 (−100%), при этом Динамика показывает живую историю групп (легаси-скелет графика). Обнаружен при визуальном ревью 5c.7.6 на симуляторе iPhone 17 Pro.

## Механизм (всё подтверждено)
1. Стор оказался чисто легаси: ZCARD=5, ZFINANCEACCOUNT=9, ZINVESTMENT=4, ZFINANCEGROUP=4, при этом **ZACCOUNT=0, ZACCOUNTEVENT=0** (ядро пусто).
2. Флаг `migration.legacyAccountsPurge.v1.millio_guest = true` стоял в UserDefaults → `runLegacyAccountsMigrationIfNeeded` (millioApp.swift:604) не перезапускается. Флаг ставится честно — только после успешной миграции (`LegacyAccountsMigrator.swift:79`, при `summary.failures == 0`).
3. Но флаг живёт в UserDefaults, а данные — в сторе. Стор был заменён ПОСЛЕ миграции версией без core-сущностей → ядро пусто, флаг стоит → UI (после contract-флипа 871dfc0 читает только ядро) пуст навсегда.

## Пути замены стора при живом флаге
- **Prod-риск: restore старого бэкапа.** `BackupManager.swift:645-674` — restore очищает/импортирует только SwiftData, **UserDefaults-флаги `migration.*` НЕ сбрасывает**. Старый бэкап (снятый до AccountsCore) не содержит core-сущностей → после restore счета невидимы, самолечения нет. Это реальный сценарий устройства владельца.
- DEBUG-путь: `rebuildStorePreservingData` (millioApp.swift:799-801) при schema-несовместимости (store → .bak.store → новый пустой). Именно он породил состояние этого симулятора.

## Эксперимент-подтверждение
Удаление ключа из plist + перезапуск → идемпотентная миграция пересоздала ядро: ZACCOUNT=9 (5 debitCard + 4 manualAsset), ZACCOUNTGROUP=4, ZACCOUNTEVENT=9. Экран «Счета» ожил.

## Рекомендация к фиксу (на решение владельца)
Предпочтительно **убрать зависимость от флага**: на старте дешёвая проверка состояния стора — «есть легаси-сущности без core-двойников → запустить миграцию (она идемпотентна)», флаг оставить лишь как быстрый short-circuit. Это самолечение для ВСЕХ путей замены стора (restore, recovery, смена скоупа). Альтернатива-минимум: restore-флоу сбрасывает per-scope `migration.*` ключи после импорта.
⚠️ Фикс касается миграции/restore = данные пользователя → по правилу 7: /stress-test + явное «да» владельца перед реализацией.
