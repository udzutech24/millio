### ⚠️ Новый вход: Фаза 5 unified-totals — вобрать в ревью плана Пути B

Владелец 2026-07-09 нашёл на симуляторе: группы целиком из AccountsCore-счетов показывают **сумму 0** в списке групп («Вклады» 5 accounts — 0 ₽ и т.д.), **«No finance products»** в редакторе группы и **«No groups»** во вкладке Groups на Analytics/Dynamics. Количество счетов при этом верное.

Диагноз (верифицирован в главной сессии, полная запись — `plans/2026-07-05__unified-totals.md` §1.3a + Фаза 5):
- `FinanceTotalsService.calculateGroupTotal` (`FinanceTotalsService.swift:148-160`) — `guard let accounts = group.accounts else { return 0.0 }`, AccountsCore не участвует; счётчик же в `FinanceRows.swift:203-208` мержит оба мира → разрыв «N accounts, но 0».
- `FinanceGroupService.orderedAccounts(for:)` (`FinanceGroupService.swift:88`) — та же legacy-связь → «No finance products» в `FinanceGroupEditorView`.
- `FinanceDynamicsViewModel.hydratedAccounts(in:)` (`FinanceDynamicsViewModel.swift:2681-2695`) + `updateDynamicsBreakdown()` (:1082-1086) — пустой legacy-список → группа выпадает из breakdown → «No groups».

**Root cause общий:** моста `FinanceGroup` ↔ `AccountGroup` нет — только временный мэппинг по имени (`AccountsCoreAdditionBridge.resolveAccountGroup`, `AccountsCoreAdditionBridge.swift:60-78`, комментарий «ВРЕМЕННЫЙ мэппинг по имени (до Фазы 6…)»). Правильный фикс — слияние групп двух миров в одну сущность («Фаза 6» из этого комментария), НЕ точечные заплатки трёх call site. Это ровно контекст Пути B — при ревью плана решить, где это живёт (отдельная фаза? внутри Фазы 6 редизайна Счетов?) и в каком порядке с миграцией Ф1.
