# 2026-07-04 — Перестройка ядра счетов: фазы 0–6a за одну автономную сессию

## Задача
Реализовать весь план `plans/2026-07-04__accounts-core-rebuild-plan.md` (event-sourcing ядро счетов,
фазы 0→6) автономно, с проверкой каждой фазы, пока Алексей отсутствовал (~3 часа, guard phrase дана).

## Как решалась
Оркестратор (главное окно) + последовательные суб-агенты «Александр» по фазе на прогон
(1a разбита на core/ui), QA-агент «Денис» на расследования тестов. Каждой фазе — письменный бриф
в scratchpad (контракт, задачи, гейт), после каждой — верификация оркестратором (коммит, grep-гейт,
выборочные прогоны). Перед 1b — /stress-test (10 рисков → митигации в бриф). Baseline тестов
зафиксирован ДО старта (16 унаследованных падений) — гейт «не хуже baseline».

## Решена ли
Да: фазы 0–5 полностью, 6a (все 11 пресетов на ядре, легаси read-only). 6b (физический снос
~90 файлов легаси-моделей) осознанно заблокирована до решения владельца (Non-Goal спеки по
backup, риск П2). ~140 новых тестов ядра. Плюс закрыт AC10-гап (append-only курсов) лично
оркестратором. Одна реальная регрессия (порядок categorySnapshots в бюджете) поймана
финальным прогоном и отдана в бисект.

## Эффективно ли
- Суб-агенты по фазам с брифами — да: контекст главного окна не раздувался, фазы шли конвейером.
- Нашлось 6+ реальных багов внутри самой сессии (двойное отрицание expense, cross-context
  SwiftData, earlyClose двойное чтение, QuickSetup в обход ядра, дубликат при правке легаси,
  перезапись исторических курсов).

## Было → стало
- Баланс с двумя хозяевами и тремя путями расчёта → единый `balanceAt` (event-sourcing),
  тотал/график/дельта — производные одной функции.
- 3 кривые модели + строковая связь → Account/AccountEvent/AccountGroup с настоящими @Relationship.
- «Плывущие» курсы/цены → append-only фиксация (события, HistoricalAssetPrice, HistoricalRateStore).
- Удаление счёта = скрытая архивация → явные две ступени (архив ↔ «удалить навсегда» с предупреждением).

## Идеи по улучшению
1. **Агенты списывают падения на flaky слишком легко.** Три фазы подряд «+2 новых падения — это flaky»;
   одно оказалось реальной регрессией, найденной только личной изоляцией оркестратора. Правило в брифы:
   не-baseline падение = обязательный изолированный прогон С ЛОГОМ в ответе.
2. LanguageManager.shared-гонка — системная болезнь тест-таргета: отдельной задачей пройтись по всем
   мутациям языка в тестах (withLanguage-паттерн). Задокументирована в baseline-файле.
3. Baseline-файл известных падений + гейт «не хуже baseline» — рабочий приём для веток от «грязного»
   develop; стоит закрепить как стандарт workspace.
4. xcresulttool: доставать текст #expect-фейла из xcresult — питоновский regex по JSON быстрее,
   чем штатная обвязка; кандидат в скилл/скрипт.
