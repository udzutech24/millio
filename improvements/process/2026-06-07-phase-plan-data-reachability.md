# Phase plan должен проверять достижимость данных downstream

## Наблюдение

Phase 2 в `plans/2026-06-07__finance-balance-contract.md` предлагала сохранить `FinanceAccount` link через `group = nil`. Это выглядело KISS, но ревизия `FinanceDynamicsViewModel` показала, что historical replay в основном пути идёт через `state.groups -> group.accounts`, а fallback при выбранных группах отбрасывает `group == nil`.

Итог: план был бы формально простым, но хрупким. Link сохранился бы в SwiftData, но мог бы стать недостижимым для расчёта динамики.

## Правило

Перед фазой, которая меняет владение/связи данных, план обязан ответить:

- кто downstream consumer этих данных;
- каким exact path он их читает;
- останутся ли данные достижимыми после изменения;
- какой тест доказывает достижимость, а не только факт сохранения в базе.

## Ожидаемый эффект

Меньше "зелёных" локальных правок, которые сохраняют объект, но ломают контракт чтения в другом модуле.
