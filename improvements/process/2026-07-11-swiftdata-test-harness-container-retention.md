# Тест-харнесс SwiftData должен держать ModelContainer живым, иначе — каскад ложных красных по чужим сьютам

**Наблюдение (2026-07-11, ночь, Ф5c.1a).** Первая версия нового тест-харнесса (`SheetsDataMapperTests`) возвращала `mainContext`, не удерживая ссылку на породивший его `ModelContainer`. Контейнер деаллоцировался сразу после возврата из setup-функции → dangling-контекст → SIGTRAP на всех 6 новых тестах. В параллельном прогоне полного `millioTests` это каскадировало в **286 ложных «красных» по совершенно чужим сьютам** — маскировало реальный результат диффа и чуть не привело к ложному выводу «регрессия» там, где регрессии не было.

**Root cause.** SwiftData `ModelContext` не удерживает свой `ModelContainer` сильной ссылкой (слабая связь по дизайну, контейнер — источник истины, контекст — view поверх него). Если тест-хелпер создаёт `let container = try ModelContainer(...)` внутри функции и возвращает только `container.mainContext`, container освобождается по выходу из функции (ARC), а `mainContext` остаётся указывать на освобождённую память — undefined behavior, не гарантированный краш именно в этом тесте (может проявиться в СОСЕДНЕМ, параллельно выполняющемся сьюте).

**Правило.**
1. Любой SwiftData-тест-харнесс обязан **сохранять `ModelContainer` в свойстве/статике теста** (не только `context`), минимум на время жизни тест-класса — не полагаться на то, что context сам удержит контейнер.
2. Если видишь **массовый** каскад красных по несвязанным сьютам после добавления НОВОГО теста — в первую очередь подозревай use-after-free в новом тест-харнессе, а не регрессию в продакшн-коде (уже второй похожий инцидент в этом проекте — см. `GroupsMigratorTests` use-after-free, 2026-07-10, коммит `3a81230`).
3. Итоги тестов проверять только через `xcrun xcresulttool` (не консольный summary xcodebuild) — этот класс багов (use-after-free) особенно склонен давать ложный «✔ passed» в консоли при реальном крахе процесса.
