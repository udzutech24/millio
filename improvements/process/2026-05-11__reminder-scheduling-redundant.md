# Cashflow reminders: 4 вызова scheduling за один запуск

**Дата:** 2026-05-11  
**Источник:** логи симулятора, запуск build 51

## Наблюдение

```
Scheduled cashflow reminders updated: 1  × 4 раза подряд
```

Метод `scheduleReminders` вызывается 4 раза в течение одного холодного старта.

## Вероятная причина

Несколько подписчиков на изменение настроек (`.onChange`, `.onReceive`, `onAppear` и т.п.) запускают одно и то же действие при инициализации. SwiftUI инициализирует View-дерево несколько раз до стабилизации состояния → каждый триггер получает первое значение и вызывает scheduling.

## Риск

- Сейчас: лишние 3 вызова `UNUserNotificationCenter` при старте. Функционально безопасно (идемпотентно).
- При добавлении нового onboarding-флоу или дополнительных Permission-запросов — количество вызовов может вырасти.
- `UNUserNotificationCenter.removePendingNotificationRequests` + `add` — синхронные в main-контексте; при большом числе уведомлений могут влиять на старт.

## Что делать

Найти все точки вызова scheduleReminders при старте, дедуплицировать через `debounce` или флаг `hasScheduledOnLaunch`. Либо перевести в `task(id:)` с явным ID — тогда SwiftUI сам дедуплицирует при ре-рендере.

## Приоритет

Низкий — не влияет на UX сейчас. Зафиксировать при следующем касании NotificationManager.
