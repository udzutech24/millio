# Локальные тестовые `Schema([...])` — молчаливый провал core-фикстур без регистрации типа

**Дата:** 2026-07-11 · **Контекст:** Ф5c.7.4+5c.7.5 contract-шаг.

## Наблюдение

Несколько тестовых файлов (`FinanceViewModelTests.swift`, `BackupRestoreIntegrityTests.swift`) строят собственный `ModelContainer` через локальный `Schema([...])` вместо переиспользования `AppMigrationPlan.makeInMemoryContainer()`. Когда контракт-флип добавил `Account`/`AccountGroup`/`AccountEvent`/`AccountDailySnapshot`-фикстуры в существующие тесты, эти типы **не были в локальной Schema** — `context.insert()`/`try context.save()` НЕ бросали ошибку, но последующий `fetch(FetchDescriptor<AccountGroup>())` тихо возвращал пусто. Итог: тесты падали на "expectation failed: nil" без явного намёка на корневую причину (тип не зарегистрирован в контейнере).

Нашёл и почини 3 раза за сессию — паттерн повторяющийся, не разовая случайность.

## Правило

- Любой новый тестовый файл, которому нужны SwiftData-модели — **предпочитать `AppMigrationPlan.makeInMemoryContainer()`** (полная актуальная схема), а не собирать `Schema([...])` вручную.
- Если локальная `Schema([...])` уже существует и её нельзя быстро заменить — при добавлении новых `@Model`-фикстур в тест **всегда сверяй список типов в Schema** первым делом, до диагностики самого assertion failure.
- Симптом для распознавания: `fetch()` после `insert()+save()` возвращает пусто БЕЗ throw — почти всегда значит "тип не в Schema контейнера", не логическая ошибка кода.

## Куда это влияет

Любая сессия, добавляющая core-модели (`Account`/`AccountGroup`/...) в существующие тесты с локальной Schema — Cashflow, Cashback, будущие миграции 5c.8+.
