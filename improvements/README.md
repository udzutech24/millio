# improvements/ — рост команды через наблюдение

Здесь копятся **предложения по улучшению** всего, что влияет на эффективность работы: сами агенты, бизнес, расход токенов, процесс. Это не свалка идей — это инструмент роста. Каждая запись должна быть **применимой** (actionable), а не «было бы неплохо».

## Принципы

1. **Пиши в момент наблюдения.** Замысел, пока контекст в голове, ≠ замысел через час.
2. **Конкретика > общих слов.** «Долго искал файл» — нет. «4 Grep'а подряд по одному символу + 3 Read'а по 400 строк перед одним Edit — надо было Explore-агент» — да.
3. **Каждая идея = файл.** Один файл = одно предложение. Проще приоритизировать и закрывать.
4. **Закрывай, когда внедрено.** Внедрил — перемести в `archive/` с пометкой где именно изменение (коммит, файл).

## Категории

| Папка | Что сюда пишем | Кто читает |
|-------|----------------|-----------|
| [agents/](agents/) | Агенты дали плохой ответ, не поняли задачу, галлюцинировали, не использовали нужный инструмент. Что добавить в CLAUDE.md / AGENTS.md / prompts.md чтобы не повторилось. | Перед крупной правкой правил и промтов |
| [business/](business/) | Факты о рынке/продукте/клиенте, которые заметил в процессе работы. Новая ниша, конкурентное преимущество, слабое место в воронке, идея для нового продукта. | Бизнес-синк / ретро |
| [tokens/](tokens/) | Конкретные инциденты «сжёг много токенов»: что тянуло контекст, какие антипаттерны сработали, как оптимизировать в следующий раз. | Перед большой сессией / при обновлении правил контекста |
| [process/](process/) | Процесс не сработал: spec → plan → code поломался, не хватало артефакта, handoff не сработал, сложно было передать чат. | Ретро / обновление CLAUDE.md workflow |

## Когда записывать

В конце каждой сессии — проходи по триггерам:

- [ ] Был ли момент, где я **думал одно, а агент сделал другое**? → `agents/`
- [ ] Была ли ситуация, где я **жёг контекст/токены сильнее ожидаемого**? → `tokens/`
- [ ] Заметил **что-то про клиента/рынок/юнит-экономику**, что раньше не фиксировал? → `business/`
- [ ] Процесс **споткнулся** (не хватило шаблона, handoff не помог, план пришлось переделывать)? → `process/`

Если хотя бы одно «да» — **пиши сейчас**, не «потом».

Инстанцирование:

```bash
cp improvements/templates/tokens.md improvements/tokens/$(date +%Y-%m-%d)-<slug>.md
```

## Формат имени файла

`YYYY-MM-DD-<slug>.md` (kebab-case, дата создания). Дата не меняется при правках.

## Жизненный цикл

1. **Открыт** — лежит в категории (`agents/`, `business/`, ...).
2. **В работе** — добавь в начало файла `Status: IN_PROGRESS` + ссылку на plan/commit.
3. **Внедрён** — `Status: DONE` + ссылка на commit/файл, где изменение. Переместить в `archive/YYYY-MM/`.
4. **Отклонён** — `Status: REJECTED` + причина. Переместить в `archive/rejected/`.

Раз в месяц/квартал — ревью открытых идей: приоритизировать / закрыть / отклонить.

## Antipattern

**НЕ пиши сюда:**
- «Надо бы улучшить» без конкретики.
- Дубли уже открытых идей — проверь сначала существующие файлы.
- Баги в коде — это в issues проекта, не сюда.
- Личные заметки — это в `thoughts/` или своё место.
