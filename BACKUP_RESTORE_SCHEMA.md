# Схема работы Backup/Restore в Millio

Документ описывает механизм резервного копирования и восстановления данных в приложении Millio.

**Версия:** 1.0  
**Дата:** 2026-01-XX

---

## 1. Архитектурные принципы

### 1.1. Offline-First подход

- Все данные хранятся **локально** в SwiftData
- Интернет используется **только** для backup/restore
- Приложение работает **полностью офлайн**

### 1.2. Snapshot-стратегия

- Backup представляет собой **полный снимок** всех данных
- Restore **полностью заменяет** локальные данные
- Нет частичного восстановления или merge данных

### 1.3. CloudKit Private Database

- Используется **только Private CloudKit Database**
- Данные доступны **только владельцу iCloud аккаунта**
- Мы не имеем доступа к данным пользователя

## 2. Схема работы Backup

### 2.1. Когда происходит Backup

#### Автоматический Backup

**Триггер:** Приложение уходит в фоновый режим

**Событие:** `UIApplication.willResignActiveNotification`

**Условия:**
- ✅ Резервное копирование включено (`appState.isBackupEnabled == true`)
- ✅ DIContainer инициализирован
- ✅ iCloud доступен (проверяется внутри `backupNow()`)

**Код:** `millioApp.swift:68-70, 108-121`

```swift
.onReceive(NotificationCenter.default.publisher(for: UIApplication.willResignActiveNotification)) { _ in
    triggerBackgroundBackup()
}
```

#### Ручной Backup

Можно добавить кнопку в UI, которая вызывает:
```swift
try await backupManager.backupNow()
```

### 2.3. Обработка ошибок

- **iCloud недоступен:** Ошибка логируется, приложение продолжает работу
- **Ошибка сети:** Retry механизм (3 попытки с экспоненциальной задержкой)
- **Ошибка шифрования:** Backup не создается, ошибка логируется

### 3.2. Важные моменты

⚠️ **Restore полностью заменяет локальные данные!**

- Все существующие локальные данные удаляются
- Данные из backup полностью заменяют локальные данные
- Нет merge или частичного восстановления

## 4. Состояния приложения

### 4.1. AppLifecycleState

```swift
enum AppLifecycleState {
    case launching    // Загрузка приложения
    case onboarding   // Онбординг (первый запуск)
    case restoring    // Восстановление данных
    case ready        // Готово к работе
    case error(AppError) // Ошибка
}
```

### 4.2. Переходы состояний

```
launching
    ↓
    ├─→ onboarding (если первый запуск)
    │       ↓
    │   completeOnboarding()
    │       ↓
    │   ready
    │
    └─→ restoring (если backup найден и включен)
            ↓
        restore() или "Продолжить без восстановления"
            ↓
        ready
```

## 5. Тестирование Backup/Restore

### 5.1. Подготовка к тестированию

#### Требования:

1. **Устройство или симулятор:**
   - iOS 18.6+
   - Активный iCloud аккаунт
   - Включен CloudKit в Capabilities

2. **Настройки приложения:**
   - Резервное копирование включено в настройках
   - Опционально: шифрование включено

3. **Тестовые данные:**
   - Создать несколько карт в "Картотека"
   - Добавить данные в другие сервисы (если есть)

---

### 5.2. Тест-кейс 1: Автоматический Backup

**Цель:** Проверить, что backup создается автоматически при уходе в фон

**Шаги:**

1. ✅ Убедиться, что резервное копирование включено
   - Открыть приложение
   - Перейти в Профиль → Настройки
   - Включить "Резервное копирование"
   - Проверить, что "iCloud доступен"

2. ✅ Создать тестовые данные
   - Добавить несколько карт в "Картотека"
   - Запомнить количество и содержимое

3. ✅ Запустить backup вручную (для проверки)
   - Можно добавить временную кнопку в UI или использовать отладку
   - Или просто уйти в фон (см. шаг 4)

4. ✅ Уйти в фоновый режим
   - Нажать Home или переключиться на другое приложение
   - Подождать 5-10 секунд

5. ✅ Проверить backup в iCloud
   - Открыть CloudKit Console
   - Проверить Private Database → Record Type "AppBackup"
   - Должен быть запись "latest_backup" с актуальной датой

**Ожидаемый результат:**
- Backup создан успешно
- В логах: "Backup completed successfully"
- В CloudKit Console видна запись с актуальной датой

---

### 5.3. Тест-кейс 2: Restore при первом запуске (после удаления)

**Цель:** Проверить восстановление данных после переустановки приложения

**Шаги:**

1. ✅ Подготовить backup
   - Выполнить Тест-кейс 1 (создать backup)
   - Запомнить количество карт и их содержимое

2. ✅ Удалить приложение
   - Долгое нажатие на иконку → Удалить приложение
   - Подтвердить удаление

3. ✅ Переустановить приложение
   - Установить из Xcode или App Store

4. ✅ Пройти онбординг
   - Завершить экран онбординга

5. ✅ Включить резервное копирование
   - Перейти в Профиль → Настройки
   - Включить "Резервное копирование"
   - Дождаться проверки iCloud

6. ✅ Проверить экран восстановления
   - Должен появиться экран RestoreView
   - Должна отображаться дата последнего backup
   - Кнопка "restore" доступна

7. ✅ Выполнить restore
   - Нажать кнопку "restore"
   - Дождаться завершения (ProgressView)

8. ✅ Проверить восстановленные данные
   - Перейти в "Картотека"
   - Проверить, что все карты восстановлены
   - Проверить содержимое карт (балансы, названия и т.д.)

**Ожидаемый результат:**
- Экран восстановления появляется автоматически
- Restore выполняется успешно
- Все данные восстановлены идентично backup
- В логах: "Restore completed successfully"

---

### 5.4. Тест-кейс 3: Restore с существующими локальными данными

**Цель:** Проверить, что restore заменяет локальные данные

**Шаги:**

1. ✅ Создать backup с данными A
   - Добавить карту "Карта A" с балансом 1000
   - Выполнить backup (уйти в фон)

2. ✅ Изменить локальные данные
   - Добавить карту "Карта B" с балансом 2000
   - Удалить "Карта A"
   - Теперь локально: только "Карта B"

3. ✅ Выполнить restore
   - Перезапустить приложение
   - Если экран restore не появился автоматически:
     - Можно добавить временную кнопку для вызова restore
   - Нажать "restore"

4. ✅ Проверить результат
   - Должна быть восстановлена "Карта A" (из backup)
   - "Карта B" должна быть удалена (не было в backup)
   - Локальные данные полностью заменены данными из backup

**Ожидаемый результат:**
- Локальные данные полностью заменены
- Данные соответствуют backup (snapshot-стратегия)
- Нет merge или частичного восстановления

---

### 5.5. Тест-кейс 4: Backup с шифрованием

**Цель:** Проверить работу backup с включенным шифрованием

**Шаги:**

1. ✅ Включить шифрование
   - Перейти в Профиль → Настройки
   - Включить шифрование backup (если есть такая опция)

2. ✅ Создать backup
   - Добавить тестовые данные
   - Уйти в фон для создания backup

3. ✅ Проверить backup в CloudKit Console
   - Backup должен быть зашифрован
   - Данные не должны быть читаемы напрямую

4. ✅ Выполнить restore
   - Удалить приложение
   - Переустановить
   - Выполнить restore

5. ✅ Проверить восстановление
   - Данные должны восстановиться корректно
   - Шифрование/расшифровка работают прозрачно

**Ожидаемый результат:**
- Backup зашифрован в CloudKit
- Restore успешно расшифровывает и восстанавливает данные
- Пользователь не замечает разницы (прозрачное шифрование)

---

### 5.6. Тест-кейс 5: Обработка ошибок

#### 5.6.1. iCloud недоступен

**Шаги:**

1. ✅ Отключить iCloud на устройстве
   - Настройки → [Ваше имя] → iCloud → Отключить

2. ✅ Попытаться создать backup
   - Включить резервное копирование
   - Уйти в фон

3. ✅ Проверить поведение
   - Backup не должен создаваться
   - Ошибка должна логироваться
   - Приложение должно продолжать работать
   - UI должен показывать "iCloud недоступен"

**Ожидаемый результат:**
- Приложение не крашится
- Ошибка обрабатывается gracefully
- Пользователь видит понятное сообщение

#### 5.6.2. Ошибка сети при backup

**Шаги:**

1. ✅ Отключить интернет
   - Включить режим "В самолете"

2. ✅ Попытаться создать backup
   - Уйти в фон

3. ✅ Проверить поведение
   - Backup не должен создаваться
   - Retry механизм должен сработать
   - Ошибка должна логироваться

**Ожидаемый результат:**
- Retry механизм пытается повторить операцию
- После восстановления сети backup должен создаться автоматически

#### 5.6.3. Backup не найден при restore

**Шаги:**

1. ✅ Удалить backup из CloudKit Console
   - CloudKit Console → Private Database → Record Type "AppBackup"
   - Удалить запись "latest_backup"

2. ✅ Попытаться выполнить restore
   - Перезапустить приложение
   - Включить резервное копирование

3. ✅ Проверить поведение
   - Должно появиться сообщение "Резервная копия не найдена"
   - Кнопка "Продолжить без восстановления" доступна
   - Приложение должно работать нормально

**Ожидаемый результат:**
- Понятное сообщение об отсутствии backup
- Возможность продолжить без восстановления
- Приложение не крашится

### 5.7. Тест-кейс 6: Производительность

   - Выполнить restore

**Ожидаемый результат:**
- Backup: < 10 секунд для 5 MB данных

### 5.8. Тест-кейс 7: Множественные устройства

**Цель:** Проверить синхронизацию backup между устройствами

**Шаги:**

1. ✅ Создать backup на устройстве A
   - Добавить данные
   - Выполнить backup

2. ✅ Восстановить на устройстве B
   - Установить приложение на устройство B
   - Войти в тот же iCloud аккаунт
   - Выполнить restore

3. ✅ Проверить синхронизацию
   - Данные должны быть идентичны на обоих устройствах
   - Изменения на одном устройстве не синхронизируются автоматически
   - Каждое устройство создает свой backup

**Ожидаемый результат:**
- Backup доступен на всех устройствах с тем же iCloud аккаунтом
- Каждое устройство работает независимо
- Нет автоматической синхронизации (только через backup/restore)

- [ ] Backup доступен на всех устройствах с тем же iCloud аккаунтом


**Restore:**
```
BackupManager: Starting restore...
BackupManager: Restore completed successfully
```

**Ошибки:**
```
BackupManager: Background backup failed: [описание ошибки]
CloudBackupStore: Failed to check iCloud availability: [описание]
```

### Проверка в CloudKit Console:

1. Открыть [CloudKit Console](https://icloud.developer.apple.com/dashboard)
2. Выбрать контейнер `iCloud.com.millio.app`
3. Private Database → Record Type `AppBackup`
4. Проверить запись `latest_backup`

## 9. Безопасность

### Защита данных:

1. **Локальное хранение:**
   - Данные в iOS sandbox (защищено системой)
   - Доступ только для приложения

2. **CloudKit:**
   - Private Database (доступ только владельцу)
   - Шифрование при передаче (HTTPS)
   - Опциональное шифрование содержимого (AES-GCM)

3. **Keychain:**
   - Ключи шифрования в защищенном хранилище
   - Не доступны другим приложениям

## 10. Заключение

Backup/Restore в Millio реализован с учетом принципов:

- ✅ **Offline-First** - приложение работает без интернета
- ✅ **Snapshot-стратегия** - полная замена данных при restore
- ✅ **Безопасность** - Private CloudKit Database, опциональное шифрование
- ✅ **Fail-Safe** - ошибки не ломают приложение
- ✅ **Прозрачность** - пользователь контролирует backup/restore

**Важно:** Restore полностью заменяет локальные данные. Пользователь должен понимать это при нажатии кнопки "restore".
